## 1. Word Card 在 LexiStudy 中的定位

### 1.1 产品作用

Word Card 是 LexiStudy 学习页的主要学习载体，负责把一个词条组织成一个稳定的回忆单元：

```text
看见提示 → 独立回忆 → 查看答案 → 判断认识程度
```

它的目标不是一次展示所有词典信息，而是让用户在当前回合内只关注一个单词和一个明确的下一步操作。

Word Card 不是：

- 词典详情页。
- 统计面板。
- AI 助手面板。
- 游戏奖励面板。
- 新增数据或业务逻辑的承载容器。

### 1.2 在学习页中的角色

学习页结构固定为：

```text
study-page
├── Header
├── Word Stage
│   └── Word Card
├── Action
│   ├── 不认识
│   └── 认识
└── Feedback
```

Word Stage 是学习内容的主舞台容器，Word Card 是其中的核心内容组件。Header、模式、进度、编号和保存说明都属于辅助层级，不能夺取 Word Card 的主要视觉焦点。

### 1.3 与学习流程的关系

Word Card 直接表达现有学习流程的三个视觉阶段：

1. **答案隐藏**：用户看到当前提示，先独立回忆。
2. **答案显示**：用户查看答案、释义、解释和例句。
3. **判断反馈**：用户选择认识或不认识，随后进入现有的下一词流程。

这是现有学习逻辑的表现层表达，不是新增业务状态。不得把它扩展为多级评分、掌握等级、连击、复习模式或 AI 辅助流程。

### 1.4 长期学习设计目标

Word Card 需要支持用户每天重复查看数十次，并在固定桌面窗口中持续学习数分钟到数十分钟。因此设计目标是：

- 安静：不持续闪烁、不持续发光、不使用强烈渐变。
- 清晰：每个状态只有一个主要视觉焦点。
- 可预测：卡片结构和操作位置在状态变化后保持稳定。
- 可读：长释义、解释、例句和字体放大时不裁剪关键内容。
- 低干扰：反馈短暂、轻量，不把学习转化为游戏奖励。
- 可持续：留白、对比度、阴影和动效适合长期重复使用。

### 3.2 竞品分析

竞品分析只借鉴设计思想，不复制功能、数据结构和业务流程。

#### qwerty-learner

可借鉴：键盘优先、单一任务焦点、辅助信息分层、即时状态反馈。

不采用：打字训练、速度和准确率统计、音频/发音系统、默写模式等会改变 LexiStudy 现有学习流程或增加数据依赖的内容。

#### 闪卡类工具

可借鉴：先隐藏答案，给用户独立回忆时间；答案揭示后再进行自我判断；卡片结构稳定。

不采用：多级评分、复杂复习按钮、收藏/笔记/关联内容、3D 翻牌和游戏化奖励动画。

#### 现代桌面学习软件

可借鉴：稳定阅读宽度、足够留白、深浅主题共享 Token、完整焦点状态、短而可中断的动效。

不采用：Dashboard 指标堆叠、侧栏辅助面板、大面积玻璃质感、复杂背景纹理、持续进度动画和会遮挡内容的固定底栏。

### 3.3 信息架构

Word Card 的逻辑层级为：

```text
Word Card
├── Primary Layer
│   ├── 单词 / 当前提示
│   └── 音标
├── Interaction Layer
│   ├── 答案隐藏提示
│   ├── 显示答案操作
│   └── 答案显示状态
├── Secondary Layer
│   ├── 中文释义
│   ├── 简短英文解释
│   └── 例句
└── Future Extension
    ├── AI 记忆技巧（v0.2.0 不显示）
    ├── 词源分析（v0.2.0 不显示）
    └── 易混词（v0.2.0 不显示）
```

答案区域的内容顺序固定为：

```text
中文释义 → 简短英文解释 → 例句
```

如果现有词条数据没有对应内容，不显示空占位、不生成假数据、不新增词库字段。

### 3.4 状态设计

状态设计围绕现有 `showAnswer`、`index` 和 `entry` 的表现层语义进行，不新增业务状态。

- State 1：答案隐藏。
- State 2：答案展开。
- State 3：判断反馈。

答案显示不等于答对；判断反馈只是短暂的视觉确认，不是新的学习算法阶段。

### 3.6 A/B/C 方案比较

项目文档中存在两组 A/B/C 讨论，新的 Chat 不要混淆：

#### 结构方案 A/B/C（早期探索）

| 方案 | 核心特征 | 主要取舍 |
|---|---|---|
| A：大卡片中心式 | 单词位于最大视觉中心，答案和操作围绕卡片组织 | 专注度高、实现简单，但视觉占比可能偏重 |
| B：信息卡片式 | 顶部单词，中部释义/解释/例句，底部操作 | 信息完整，但容易变成词典详情面板 |
| C：渐进展开式 | 单词 → 答案 → 反馈分阶段出现 | 节奏明确，但状态边界和布局跳动控制更复杂 |

早期设计计划推荐 A；当前视觉阶段冻结为 B「中等比例卡片」，不是将 B 解释为信息卡片式结构，而是指卡片视觉比例方案。

#### 视觉方向 A/B/C（当前视觉探索）

| 方向 | 视觉气质 | 优点 | 风险 | 学习场景适配 |
|---|---|---|---|---|
| A：桌面生产力工具风格 | 结构化、克制、稳定，参考 Linear / Notion 类产品 | 适合长期桌面学习，易与学习页 Token 统一 | 边框和阴影过重时会像后台 | 最适合 v0.2.0 |
| B：极简闪卡风格 | 大留白、弱边界、单焦点 | 回忆任务直接，视觉噪声低 | 答案展开后可能缺乏容器层级 | 适合短时高频复习 |
| C：现代 AI 学习工具风格 | 智能、流动、即时反馈、科技感 | 品牌新鲜感强，未来扩展空间大 | 容易使用光晕、渐变和强反馈，增加疲劳 | 当前版本不作为主方向 |

当前推荐视觉方向为 **A**，吸收方向 B 的留白控制；不采用方向 C 的 AI 光晕、强渐变和游戏化装饰。

### 3.7 Taste Skill 评估

已从以下维度进行视觉质量评估：

- 单词是否是唯一明确的视觉主角。
- 卡片比例、留白和信息层级是否适合长期重复使用。
- 深色主题中的光晕、阴影、对比度和视觉疲劳风险。
- 浅色主题中的边框、阴影、灰字和可读性风险。
- 动效是否提供轻微触感，而不是游戏化刺激。
- 是否出现通用模板、卡片堆叠、装饰性渐变或信息面板泛滥。

Taste Skill 的通用高端视觉建议不能覆盖 LexiStudy 现有 Design System。不得为 Word Card 强行引入新字体、玻璃风格、双层 bezel、复杂渐变、大面积插画或持续发光。

### 3.8 人工审核节点

人工审核必须覆盖：

- 卡片视觉重量。
- 卡片占屏比例。
- 阴影强弱和边框对比。
- 单词字号和长单词表现。
- 音标位置、字号和视觉权重。
- State 1 与 State 2 的留白差异。
- 答案展开是否稳定，是否产生明显布局跳动。
- 中文释义、英文解释和例句的信息密度。
- Dark / Light 主题是否共享同一语义层级。
- 连续学习 30–60 分钟后的视觉疲劳风险。

## 4. 已冻结的重要设计决策

本节是新的 Word Card Visual Design Chat 最重要的执行基线。

### 4.1 视觉方向

#### 推荐方案

推荐 **方向 A：桌面生产力工具风格**。

具体表现：

- 参考 Linear / Notion 类产品的结构化、克制和稳定感。
- 使用清晰但低对比的卡片边界。
- 使用单层、低层级阴影，不堆叠多层阴影。
- 用排版、层级和留白建立质感，不依赖装饰性渐变或光晕。
- 吸收方向 B 的极简留白，但保留足够容器边界，确保学习页结构清晰。

#### 不采用方向

- 不采用方向 C 的强 AI 科技感作为 v0.2.0 主视觉。
- 不使用持续发光、霓虹边框、大面积渐变、复杂背景纹理或奖励式动效。
- 不将 Word Card 设计为信息密集的词典详情面板。
- 不将卡片设计为游戏化翻牌或 3D 旋转组件。

### 4.2 卡片结构

当前冻结为 **方案 B：中等比例卡片**。

#### 单词区域

- 单词是第一视觉中心。
- 单词字号固定为 `56px`。
- 英译中模式显示英文单词；中译英模式显示中文当前提示。
- 单词正文不被图标、插画或装饰边框抢占焦点。

#### 提示区域

- 音标位于英文单词下方。
- 音标是辅助信息，字号、字重、颜色和对比度低于单词正文。
- 若现有词条没有音标，不显示空占位，不新增音标字段。
- 答案隐藏阶段不显示中文释义、英文解释和例句，避免削弱主动回忆。

#### 答案区域

- 答案在卡片内部展开。
- State 2 新增中文释义、简短英文解释和例句。
- 内容顺序为：中文释义 → 简短英文解释 → 例句。
- 答案区使用卡片内部的分隔关系或低对比层级，不嵌套厚重的第二张卡片。
- 答案展开允许自然增高，但不能通过裁剪、固定高度或 `overflow: hidden` 隐藏关键内容。

#### 操作区域关系

- `显示答案` 是答案隐藏阶段的卡片内 primary action。
- `认识 / 不认识` 位于卡片下方的 Action 区域，不嵌入答案正文。
- 答案隐藏时判断按钮可见但 disabled，位置保持稳定。
- 答案显示后判断按钮同时启用，两个按钮等宽、相邻、同等可见。
- 最小点击区域约为 `44×44px`。
- 当前视觉设计不新增音频、收藏、评分、笔记或 AI 操作。

### 4.3 Typography

所有 Typography 必须接入项目已有 Font Scale 和 Typography Token。以下是当前视觉目标值：

| 内容 | 目标字号 | 行高建议 | 层级 |
|---|---:|---:|---|
| 单词 | **56px** | 1.05–1.1 | 主视觉中心 |
| 音标 | 18px | 1.4 | 单词辅助信息 |
| 中文释义 | 24px | 1.45 | 答案主要内容 |
| 简短英文解释 | 16px | 1.55 | 答案辅助内容 |
| 例句 | 17px | 1.6 | 语境辅助阅读 |
| 反馈文字 | 14–16px | 1.4 | 短暂状态提示 |

Typography 规则：

- 单词使用主文字 Token。
- 音标使用次级文字 Token，但必须保持可读。
- 中文释义不低于英文解释的视觉权重。
- 例句使用较宽松的行高，不把学习回合变成阅读任务。
- 不能因为 Taste Skill 偏好而引入新的字体依赖。

### 4.4 Layout

| 项目 | 当前冻结方向 |
|---|---|
| 卡片方案 | B：中等比例卡片 |
| 卡片最大宽度 | `720px` |
| State 1 视觉基准 | 约 `1.55:1`，可参考 720 × 460px |
| State 2 高度 | 内容展开后自然增加，目标不超过约 560px；不强行压缩内容 |
| 内容阅读宽度 | 约 `600px`，避免例句行长过长 |
| 桌面内边距 | 建议上下 48px、左右 56px，实际使用现有 Spacing Token |
| 圆角 | 继承项目卡片级 `Radius Token`，优先 `var(--radius-card)` |
| 阴影 | 继承 `Shadow Token` 的低层级卡片阴影，优先 `var(--shadow-card)` |
| 边框 | 继承现有弱边框/分隔线语义 Token，约 1px 视觉边界 |
| 卡片背景 | 现有 elevated / raised surface Token |
| 页面背景 | 现有 page / canvas surface Token |

补充规则：

- 比例是视觉基准，不是必须固定的 CSS 高度。
- State 2 允许自然增高，长文本优先完整可读。
- 不能机械保留现有代码中的 `min-height: 430px`，需要在实现阶段按响应式设计重新评估。
- 卡片不能同时使用高对比边框、明显阴影和大面积强调色。

### 4.5 State Design

#### State 1：答案隐藏

显示：

- 单词或当前提示。
- 音标。
- 答案隐藏提示或“准备好后查看答案”。
- `显示答案` 操作。

隐藏：

- 中文释义。
- 简短英文解释。
- 例句。

视觉目标：把注意力集中在“看到单词 → 独立回忆 → 准备揭示”上。不得显示模糊答案、预览片段、倒计时或自动揭示提示。

#### State 2：答案展开

新增：

- 中文释义。
- 简短英文解释。
- 例句。

视觉目标：用户从主动回忆切换到答案核对和语境理解。单词和音标位置尽量稳定，答案区域从卡片内部出现；不能产生大幅布局跳动。

#### State 3：判断反馈

提供轻量反馈：

- 被点击的判断按钮短暂显示 active。
- 认识使用现有 success 语义。
- 不认识使用现有 danger / error 语义。
- 颜色必须与文字、位置、焦点共同表达含义。
- 旧答案和旧反馈在下一词出现时清除。

不显示：

- 分数。
- 连击。
- 奖励。
- 音效。
- 弹窗。
- 新的完成指标。

### 4.6 Dark / Light 主题

V2.2 最终主题方案：

- Dark Mode：方案 A。
- Light Mode：方案 B。

这里的 A/B 指主题视觉方案，不改变当前冻结的方案 B 中等比例卡片结构。两种主题只改变 Token 映射，不改变内容顺序、按钮位置、交互语义或快捷键语义。

禁止创建新的颜色体系。只允许使用既有语义 Token：

| 语义 | 现有 Token 方向 |
|---|---|
| 页面背景 | `--color-bg` / page surface |
| 卡片背景 | `--color-surface-elevated` |
| 主文字 | `--color-text` / text.primary |
| 次级文字 | `--color-text-muted` / `--color-text-subtle` |
| 主行动 | `--color-brand` / `--color-brand-strong` |
| 认识/完成 | `--color-success` / `--color-success-surface` |
| 不认识/错误 | `--color-danger` / `--color-danger-soft` |
| 焦点 | `--color-focus` / `--shadow-focus` |
| 卡片圆角 | `--radius-card` |
| 卡片阴影 | `--shadow-card` |

Light / Dark 只改变 Token 映射，不改变：

- 内容顺序。
- 卡片结构。
- 按钮位置。
- 交互语义。
- 快捷键语义。
- 信息密度目标。

Dark Mode 重点避免死黑、过强光晕和发光边框；Light Mode 重点避免灰字 on 浅色背景、过度依赖阴影和边界对比不足。

### 4.7 动效

动效采用 LexiStudy 的 “quiet kinetic” 原则：轻、短、可预测。

- 答案展开：约 `180–240ms`，优先透明度与轻微状态过渡。
- 判断反馈：约 `120–180ms`，主要表现为 active、边框或反馈文字变化。
- 下一词过渡：约 `160–240ms`，不得阻塞操作。
- 不动画卡片高度、padding、按钮位置或页面整体布局。
- 不使用大幅滑屏、旋转、翻牌、持续发光或循环动画。
- `prefers-reduced-motion: reduce` 时取消非必要位移、模糊、连续动画和非必要淡入，只保留静态状态变化。

### 5.2 Taste Skill 评估内容

Taste Skill 作为视觉质量评估方法使用，重点检查：

- 组件是否有清晰主角。
- 视觉重量是否适合高频重复。
- 留白是否服务于回忆，而不是装饰。

- 动效是否提供触感但不过度游戏化。

## 7. 与 Learning Page UI 的关系

### 7.1 Word Card 不是独立页面

Word Card 只属于学习页，不应被实现为独立路由、独立业务模块或词典详情页。它的上下文是完整学习页中的一个回合：当前提示、答案、判断和下一词。

### 7.2 与 Header 的关系

- Header 提供学习模式、计数和页面级信息。
- Header 视觉层级低于 Word Card，但必须保持可见。
- Word Card 不复制 Header 的进度、模式或编号信息。
- Header 的存在不能迫使 Word Card 过度压缩或占满 viewport。

### 7.3 与 Word Stage 的关系

- Word Stage 是稳定、居中、低干扰的内容舞台。
- Word Card 是 Word Stage 内唯一主要视觉焦点。
- 多余窗口高度转换为呼吸感，不转换为统计、计时器、奖励或 AI 面板。
- Word Stage 不是新的业务状态或数据容器。

### 7.4 与 Action 的关系

- `显示答案` 属于卡片内部的答案揭示操作。
- `认识 / 不认识` 属于卡片下方的 Action 区域。
- Action 不应放在固定底栏中，以免遮挡紧凑窗口或字体放大后的内容。
- 答案隐藏时判断按钮可见但 disabled，保证位置稳定。
- 答案显示后判断按钮同时启用，等宽、相邻、同等可见。

### 7.5 与 Feedback 的关系

- Feedback 负责短暂确认当前判断已被接受。
- 不新增 toast、弹窗、分数、连击、音效或游戏奖励。
- 下一词出现时，旧答案和旧反馈必须清除。
- Feedback 不能覆盖 Word Card 的核心内容，也不能成为新的视觉主角。
