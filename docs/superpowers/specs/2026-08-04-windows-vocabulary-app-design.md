# Windows 本地英语背词软件设计

## 目标

创建一个仅运行于 Windows 的本地英语背词桌面应用。应用使用固定的 `vocabulary_final.json` 作为只读词库，学习记录与词库文件完全分离，并为未来迁移到 SQLite 预留清晰的数据访问接口。

## 范围

第一阶段包含 Electron + React + TypeScript + Vite 项目骨架、固定词库读取、基础导航和四个页面：首页、学习页、统计页、设置页。首页显示词库总数和当前学习进度；学习页显示一个英文单词、答案按钮以及“认识/不认识”按钮的基础交互。

第一阶段暂不实现完整复习算法、SQLite 数据库、正式统计计算、PDF 导入、账号、云同步、联网功能或打包发布流程。

## 核心约束

- `vocabulary_final.json` 是固定只读资源，程序运行时不得写入、覆盖、删除或重新排序。
- 所有学习进度、答题记录和未来的复习状态写入独立的数据存储层，不回写 JSON。
- 数据访问通过接口隔离 UI 与具体存储实现，第一阶段使用内存/占位实现，后续可替换为 SQLite 实现。
- Electron 仅作为 Windows 本地桌面容器，不配置网络请求、账号体系、云服务或远程数据同步。
- 词条使用原始 `id`、`word`、`meaning` 三个字段；应用不依赖词条数组下标作为永久标识。

## 架构

### Electron 主进程

`electron/main.ts` 创建 BrowserWindow、设置安全的窗口选项，并在应用启动时定位固定词库资源。`electron/preload.ts` 通过 `contextBridge` 暴露最小化的本地 API，例如读取固定词库和调用学习数据存储接口，避免渲染进程直接访问 Node.js 或文件系统。

### React 渲染进程

`src/App.tsx` 管理页面路由和应用级状态。页面组件只处理展示与用户操作，通过服务接口获取词库和学习状态，不直接读写文件。

### 词库服务

词库服务负责校验 JSON 的数组结构、字段类型和基本完整性，并返回只读词条集合。服务不提供写入词库的方法，从接口层阻止误修改固定词库。

### 学习数据服务

学习数据服务定义独立的数据模型和接口，例如读取进度、保存答题结果、读取统计摘要。第一阶段提供内存占位实现；后续增加 SQLite 实现时，只替换服务实现与 Electron IPC 绑定，不修改页面的主要交互。

## 数据流

```text
固定 vocabulary_final.json
        ↓ 只读加载
Electron 主进程 / preload API
        ↓
React 词库服务 → 首页、学习页、统计页

用户答题 → 学习数据服务 → 独立存储
                                  ↓
                         未来替换为 SQLite
```

应用启动时加载词库并建立只读内存副本；用户开始学习后，学习页从词库服务按原始顺序读取词条。答题动作只写入学习数据服务，不触碰词库资源。

## 页面结构

- 首页：显示词库总数、当前进度、已学习数量和进入学习按钮。
- 学习页：一次显示一个英文单词；点击“显示答案”后显示中文释义，再提供“认识”和“不认识”按钮。
- 统计页：第一阶段提供占位布局，预留总词数、学习次数、正确率和当前进度区域。
- 设置页：第一阶段提供占位布局，预留主题、学习数量和快捷键设置区域。

界面采用深色优先、简洁卡片布局和左侧导航，保留清晰的学习主区域，风格接近 Anki 但不复制其具体界面。

## 错误处理

- 固定词库不存在、无法解析或结构不正确时，主界面显示明确的本地错误页，不尝试联网或自动下载。
- 学习数据保存失败时，保留当前界面状态并显示保存失败提示；不得修改词库文件作为回退方案。
- 页面只依赖服务返回的结构化错误，不直接显示底层文件系统异常堆栈。

## 测试与验收

- 启动开发命令后 Electron 窗口正常打开。
- 启动时能够读取 `resources/vocabulary_final.json`，并显示正确的总词数。
- 首页、学习页、统计页、设置页均可通过导航访问。
- 学习页显示第一个词条，点击按钮可以显示释义并切换到基础下一步状态。
- 运行前后固定 JSON 文件内容、词条顺序和文件修改时间不发生变化。
- 学习数据服务接口可被独立测试，并且不依赖词库写入能力。
