# LexiStudy v0.2.0 学习页 UX 设计

## 状态

- 版本：v0.2.0-alpha
- 分支：`feature/v0.2.0-learning-page`
- 阶段：UX 方案设计完成，待文档审阅
- 设计范围：UI/UX Enhancement Only

## 目标

在不改变学习算法、学习数据流程、快捷键语义、SQLite、IPC 或路由的前提下，优化学习页的专注度、状态可理解性、长期使用舒适度和窗口适配能力。

学习页只围绕以下固定节奏组织：

```text
看到提示 → 独立回忆 → 显示答案 → 判断认识程度 → 进入下一词
```

## 设计决策

采用“节奏卡片”作为唯一主方案：单词卡负责提示与答案，卡片下方固定放置“认识/不认识”判断操作。答案显示后允许有轻量状态提示，但不改变布局或按钮位置。

该方案优先保证：

- 单词内容是页面唯一主视觉焦点。
- 显示答案与判断答案的阶段边界清晰。
- 鼠标和键盘操作具有一致的视觉结果。
- 长时间学习时页面节奏稳定、低干扰。
- 紧凑窗口和字体放大时仍然完整可用。

## 页面骨架

```text
学习页
├── 顶部信息栏
│   ├── 学习中 / 新词练习
│   ├── 英译中 / 中译英
│   └── 当前进度：12 / 35
├── 单词卡
│   ├── WORD 0012
│   ├── 当前提示
│   ├── 固定高度的答案区域
│   └── 显示答案 · Space
├── 判断操作区
│   ├── 不认识 · ←
│   └── 认识 · →
└── 低强调辅助说明
```

页面继续使用现有 AppShell 和路由。学习页不新增侧栏、统计模块、弹窗、奖励模块或新的业务入口。

### 布局规则

- 单词卡是页面最高视觉层级。
- 答案区域预留稳定空间，显示答案后不推动判断按钮大幅移动。
- “认识 / 不认识”保持等宽、相邻和固定位置。
- 答案未显示时，判断按钮保持可见但 disabled。
- 顶部标题、模式和进度可在紧凑窗口下自然换行。
- 页面可以纵向滚动，但不得产生横向溢出。

## 状态矩阵

| 阶段 | 单词卡 | 显示答案 | 判断按钮 | 辅助提示 |
|---|---|---|---|---|
| 提示阶段 | 显示单词或中文释义 | 可用 | 可见但 disabled | 准备好后查看答案 |
| 答案阶段 | 显示答案，使用成功语义色 | disabled | 同时启用 | 请选择你的判断 |
| 下一词 | 清除旧答案并显示新提示 | 恢复可用 | 恢复 disabled | 回到提示阶段 |

### 交互与反馈

- Space 只负责显示答案，不直接提交判断。
- Left Arrow 触发“不认识”，Right Arrow 触发“认识”。
- Esc 继续返回首页。
- 答案显示使用短暂透明度过渡，卡片尺寸保持不变。
- 判断提交使用轻微 active 反馈，然后进入下一词。
- 下一词只使用 `opacity` 与 `transform` 过渡，不动画布局尺寸。
- `prefers-reduced-motion: reduce` 时取消位移和非必要过渡。
- 颜色不承担唯一语义；按钮始终保留“认识 / 不认识”文字。
- 保持 `focus-visible`、清晰按钮文本和键盘提示。

不新增业务状态；状态继续由现有 `showAnswer`、`index` 和 `entry` 派生。

## 响应式规则

### 标准窗口：约 `1180×760`

- 顶部信息保持一行。
- 学习内容最大宽度约 `1080px`。
- 单词正文最大阅读宽度约 `760px`。
- 判断按钮保持两列等宽。
- 多余空间转化为上下留白，不增加新模块。

### 紧凑窗口：约 `920×620`

- 顶部信息允许换行，模式和进度保持可见。
- 减少卡片内边距，但保留答案区域和完整点击区域。
- 不通过固定高度强行撑满窗口。
- 允许纵向滚动，禁止横向溢出。

### 宽屏与全屏

- 内容保持合理最大宽度，避免全屏过度拉伸。
- 单词字号不随窗口无限放大。
- 单词卡和操作区保持紧密关联。
- 增加呼吸空间，而不是增加信息密度。

### 字体缩放

100%、125%、150%、175% 四档缩放均需保证长英文单词、中文释义、答案、按钮、快捷键和进度数字完整可读；必要时增加页面高度，不裁剪内容或压缩正文。

## 主题与视觉 Token

学习页继续继承项目现有 Theme、Typography、Layout、Radius、Shadow 和 Animation Token，不创建独立颜色体系。

- 页面背景使用全局 `--color-bg`。
- 单词卡使用 `--color-surface-elevated`、边框 Token 和卡片阴影 Token。
- 单词正文使用 `--color-text`。
- 编号、进度和辅助说明使用 muted/subtle 文字 Token。
- 显示答案使用成功语义 Token。
- “认识 / 不认识”分别映射成功与错误语义 Token。
- 焦点使用统一 focus Token。
- 不新增强烈渐变、插画、装饰性光效或游戏化奖励表现。

## 实现边界

### 允许修改

- `src/pages/StudyPage.tsx` 的展示层 class、语义属性和布局包裹。
- `src/styles/global.css` 中学习页相关样式。
- 学习页的轻量入场、状态过渡、按钮反馈和响应式样式。

### 禁止修改

- `getFrontText`、`getAnswerText` 和 `handleStudyKeyDown`。
- `onAnswer`、`onIndexChange`、`onModeChange` 的调用和语义。
- 学习算法、学习队列、掌握等级、答题记录和进度计算。
- SQLite 表结构、保存时机、IPC、Electron、preload 和文件访问逻辑。
- 词库 JSON、词库顺序、词库导入和数据流程。
- 新增业务组件、业务状态、学习阶段或新功能。

## 验收场景

1. 初始状态能立即识别单词、模式、进度和下一步操作。
2. 显示答案后答案完整出现，判断按钮启用且位置稳定。
3. 鼠标与 Space、Left Arrow、Right Arrow、Esc 的现有语义保持一致。
4. 进入下一词后旧答案清除，计数同步，无重复提交。
5. 完成状态继续使用现有“今日目标已完成”和“再学一轮”流程。
6. `920×620`、`1180×760`、宽屏和全屏无横向溢出或遮挡。
7. 100%、125%、150%、175% 字体缩放不造成重叠或裁剪。
8. 深色、浅色和 reduced-motion 环境下均可正常使用。
9. 现有测试和构建通过，变更范围不涉及算法、数据层和 IPC。
