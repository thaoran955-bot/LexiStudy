# LexiStudy v0.2.0 首页视觉改造规划

## 0. 改造边界

本规划只服务于 LexiStudy v0.2.0 的 UI/UX Enhancement Only 目标：优化首页的视觉层级、空间比例、主题适配、字体、图标和动效，不增加任何业务功能。

禁止修改：

- SQLite 数据库结构、学习记录和设置保存逻辑。
- 学习算法、学习队列、掌握等级和错词复习逻辑。
- 词库 JSON、词库格式、词库导入和词库切换逻辑。
- preload、IPC channel、Electron 数据通信和路由语义。
- 首页现有的开始学习、继续学习、选择词库和每日目标操作含义。

首页改造只允许改变展示结构、CSS class、视觉 token、可访问性属性和表现层动画。

## 1. 当前结构分析

### 1.1 HomePage.tsx 结构

当前 `HomePage` 接收以下现有数据和回调：

- `progress`：总词数、已答题数、认识数和不认识数。
- `dailyTarget`：当前每日 35/50 目标。
- `sessionIndex`、`sessionLength`：学习进度和当前学习队列长度。
- `currentDictionary`：当前词库名称、来源和词数。
- `onTargetChange`：保存每日目标。
- `onStartSession`：完成一轮后重新开始。

组件内部只计算两个展示状态：

- `hasProgress`：当前是否存在未完成学习进度。
- `isComplete`：当前学习轮次是否完成。

这说明首页目前没有独立的业务状态，视觉改造不需要新增数据流。

### 1.2 当前页面顺序

当前页面从上到下依次为：

1. `page-header`：问候语、每日目标说明和开始/继续/再学一轮按钮。
2. `current-dictionary-panel`：当前词库信息和“选择词库”入口。
3. `ProgressCard`：今日学习百分比、已学习数量和环形进度。
4. `target-panel`：35/50 个新词目标按钮。
5. `metric-grid`：词库总数、今日已学、认识三个指标。
6. `info-panel`：学习提示和装饰性星光符号。

### 1.3 ProgressCard.tsx 结构

`ProgressCard` 是纯展示组件，接收 `dailyTarget`、`sessionIndex` 和 `totalWords`，内部计算今日目标百分比，并渲染：

- “词库学习进度” eyebrow。
- 大号百分比数字。
- 今日已学习和目标说明。
- 使用 CSS `conic-gradient` 绘制的环形进度。

它没有学习数据写入、数据库调用或用户交互回调，适合保留为独立展示组件，只调整 class 和视觉结构。

### 1.4 AppShell 对首页的影响

`AppShell` 提供全局侧栏、左侧导航、侧栏当前进度和 `.content-area`。首页因此已经具备桌面应用外壳，不应在 `HomePage` 中重复创建导航。

当前外壳的视觉限制：

- 侧栏宽度固定约 `238px`。
- `.content-area` 使用固定 `56px 72px` 内边距和 `1160px` 最大宽度。
- `.page-stack` 再次限制为 `920px`，导致宽屏存在额外空白。
- `body` 最小宽度为 `920px`，首页只有一个 `1050px` 断点。

## 2. 当前视觉差距分析

### 2.1 信息层级

- 页面中有多个同等重量的卡片，主任务“开始/继续今天的学习”没有足够明确的聚焦区。
- `ProgressCard` 是首页最重要的信息，但当前与词库面板、目标面板、指标卡使用相近的边框和背景层级。
- 侧栏已经显示一次当前进度，首页又显示百分比、已学数量和指标，存在信息重复，需要通过层级而不是删除业务信息来区分。
- 学习提示位于页面末端，当前使用装饰性 `✦`，视觉价值低于主要 CTA。

### 2.2 空间比例

- 固定 `.page-stack { max-width: 920px; }` 无法充分利用宽屏和全屏空间。
- 进度卡 `min-height: 220px`、大数字 `68px` 和环形进度 `132px` 在紧凑窗口中比例偏重，在宽屏中又显得内容稀疏。
- 当前目标面板、指标网格和提示面板连续纵向堆叠，页面较长，首屏不一定同时看到主任务和今日目标。
- `metric-grid` 使用 `repeat(3, 1fr)`，没有 `minmax(0, 1fr)`，长文本或窄窗口可能造成挤压。

### 2.3 色彩与组件层级

- 当前首页大量使用硬编码的深灰背景、边框和黄绿色主色，尚未接入视觉系统中的语义 token。
- 视觉系统要求品牌蓝承担主行动和 active 语义，黄绿色只承担认识、完成和进度提升；当前首页主 CTA 仍然使用黄绿色，需调整为品牌蓝。
- 当前卡片普遍使用 `1px` 边框，缺少背景层级、内侧高光和空间留白的区分。
- 浅色主题没有对应的首页表面、边框和状态色实现规则。

### 2.4 字体与图标

- 当前字体为 `Inter, Microsoft YaHei, system-ui`，与视觉系统确定的 Windows 可实现字体栈不一致。
- 页面标题、68px 进度数字、说明文字和按钮字号之间缺少统一的 `--font-scale` 联动规则。
- “→”和“✦”等 Unicode 字符可能受 Windows 字体影响，尺寸和基线不稳定。
- 首页没有清晰区分品牌图标、操作图标和状态图标。

### 2.5 响应式与窗口状态

- 当前首页主要依赖 `1050px` 单一媒体查询，不能细致覆盖 `920×620`、`1180×760` 和全屏状态。
- 当前词库面板、目标面板和页面标题只在现有媒体查询中纵向调整，缺少统一的 `clamp()` 间距和可伸缩网格。
- 全屏时页面容器不会随着可用空间合理扩展，容易出现左右空白。
- 加载、最大化和全屏时的白边/白闪需要由全局背景 token 统一处理，首页不能单独设置冲突背景。

## 3. 新版首页布局规划

### 3.1 目标布局

保留现有信息和操作，只重新组织视觉层级：

```text
HomePage
└── home-page / page-stack
    ├── home-hero
    │   ├── greeting + page title + daily target description
    │   └── primary CTA: 开始学习 / 继续学习 / 再学一轮
    ├── dictionary-context
    │   ├── current dictionary name / source / word count
    │   └── secondary CTA: 选择词库
    ├── home-focus-grid
    │   ├── ProgressCard：今日学习主进度
    │   └── target-panel：35/50 今日目标
    ├── home-metrics
    │   └── 现有三个指标：总词数 / 今日已学 / 认识
    └── home-guidance
        └── 现有学习提示
```

这只是展示结构规划，不代表新增 React 业务组件。可以使用现有 section 和 presentation-only wrapper 完成布局，不改变 props 和回调。

### 3.2 首屏优先级

标准窗口和全屏状态下，首屏优先保证：

1. 页面标题和开始/继续学习 CTA。
2. 当前词库上下文。
3. 今日学习进度。
4. 今日目标选择。

指标卡和学习提示可以在首屏下方自然滚动，不与主任务争夺视觉焦点。

### 3.3 Home Hero

- 继续使用现有问候语、标题、目标说明和 CTA 文案。
- 宽窗口下标题区和 CTA 横向排列，紧凑窗口下纵向排列。
- CTA 使用品牌蓝，按钮采用清晰的主操作样式；完成状态可以使用成功色表达，但不改变点击行为。
- CTA 的箭头替换为统一的本地图标或 presentation-only SVG，点击仍然使用现有 `Link` 和 `onStartSession`。
- eyebrow 使用视觉系统的 label token，不再独立硬编码字母间距和颜色。

### 3.4 Dictionary Context

- 继续显示词库名称、词数和“内置词库/用户导入”来源。
- 以轻量上下文条或低层级面板承载，不与主进度卡使用同等视觉重量。
- 长词库名称允许换行或省略，选择词库按钮必须保持可见。
- 使用语义状态标签区分内置和用户导入，不新增词库信息。
- 选择词库入口仍然导航到现有 `/dictionaries` 路由。

### 3.5 Home Focus Grid

- 宽窗口使用约 `7:5` 或 `1.25fr 1fr` 的主进度/目标布局。
- 紧凑窗口降为单列，先显示主进度，再显示目标选择。
- `ProgressCard` 仍然显示百分比、已学习数量和目标数量，不新增数据。
- 环形进度使用品牌蓝作为主行动色；达到目标时可使用成功色表达完成状态。
- 目标按钮保持 35/50 两个选项，使用统一 control token、focus-visible 和 selected 状态。
- 进度卡和目标面板使用不同表面层级，避免两个区域看起来像重复卡片。

### 3.6 Metrics

- 保留三个现有指标，不增加新的统计字段。
- 宽窗口使用三列 `minmax(0, 1fr)`；紧凑窗口使用两列或一列，依据实际内容宽度决定。
- “词库总数”“今日已学”“认识”分别使用 label、数字和辅助说明的统一排版。
- 数字使用稳定的数字宽度和 `--font-scale`，避免窗口变化时跳动。
- 为未来 Stats Dashboard 只保留视觉上的扩展边界，不在首页添加新的图表、趋势或统计卡。

### 3.7 Guidance

- 保留现有“每次只专注一个单词”和学习提示文案。
- 降低其视觉权重，作为页面底部的轻量提示，不使用过大的装饰图标。
- 将 `✦` 替换为统一的低强调提示图标，或在没有必要时仅使用文字提示。

## 4. 主题适配方案

### 4.1 深色模式

- 首页背景使用 `--color-bg` / `--color-bg-soft`，保留低对比蓝色环境光。
- 主进度卡使用 `--color-surface-elevated`，普通上下文和指标面板使用 `--color-surface`。
- 主 CTA 和 active 控件使用 `--color-brand` / `--color-brand-strong`。
- 认识、完成和满进度使用 `--color-success`，不把所有按钮都染成绿色。
- 边框使用 `--color-border`，不继续为每个面板单独硬编码灰色边框。

### 4.2 浅色模式

- 页面背景使用浅蓝灰 `--color-bg`，卡片使用 `--color-surface` 和 `--color-surface-elevated`。
- 品牌蓝使用浅色主题对应值，保证 CTA 和链接达到可读对比度。
- 进度环、选中目标和来源标签使用同一套语义色映射，不直接复用深色颜色。
- 不改变组件顺序、数据内容、按钮行为和导航路径。

### 4.3 白边和窗口统一

- 首页不设置独立的白色背景；根节点、页面背景、加载态和错误态使用全局 token。
- 在 `920×620`、`1180×760`、最大化和全屏状态验证没有白边、白闪或内容断层。
- Electron 窗口背景色调整属于窗口表现层规划，不能触碰加载路径、数据库初始化或 IPC。

## 5. 字体适配方案

### 5.1 运行时字体栈

使用视觉系统确定的可实现字体栈：

```text
Segoe UI Variable,
Segoe UI,
Microsoft YaHei UI,
Microsoft YaHei,
system-ui,
sans-serif
```

`Plus Jakarta Sans` 或 `Geist Sans` 只作为可选品牌字体方向；如果没有随应用本地提供，不联网下载，直接使用默认栈。

### 5.2 首页字号角色

- Home hero 标题：`28–36px`。
- 进度百分比：`40–56px`，不再固定为单一 `68px`。
- 面板标题：`16–20px`。
- 正文和词库说明：`13–15px`。
- eyebrow、指标标签和辅助说明：`10–12px`。

所有字号通过 `--font-scale` 的 `0.9 / 1 / 1.1` 三档联动。字体缩放不得造成 CTA、目标按钮、词库名称或指标数字重叠。

## 6. 图标替换方案

- 保留 Windows 应用图标 `assets/icon.ico`，不在首页重新制作品牌图形。
- 将 HomePage 中的 `→`、`✦` 等 Unicode 装饰替换为统一的 24×24 本地图标或 presentation-only SVG。
- CTA 箭头使用轻量、单线、round linecap/linejoin 图标，尺寸约 `14–16px`。
- 学习提示图标使用低强调的 `20–24px` 图标，颜色使用 `--color-text-muted` 或 `--color-brand` 的低强调版本。
- 图标不能承载新的交互，不新增图标菜单、快捷操作或业务状态。
- 图标必须与旁边文字共同表达含义，并支持 focus-visible 和高对比度主题。

## 7. 动效规划

### 7.1 页面进入

- 首页内容使用轻量的分组淡入/上移，建议 `160–240ms`，不使用大幅滑入。
- Hero、词库上下文、主进度、目标和指标可以按视觉层级轻微错峰，但不延迟用户点击 CTA。
- 只动画 `transform` 和 `opacity`，使用 `cubic-bezier(0.32, 0.72, 0, 1)` 等自然减速曲线。

### 7.2 进度反馈

- 环形进度和进度数字可以在数据更新后短暂过渡。
- 进度值必须立即保持准确，动画不能改变学习状态或保存时机。
- 达到目标时可以使用一次轻微的成功高光，但不添加音效、粒子或游戏化奖励。

### 7.3 交互状态

- CTA、目标按钮、选择词库按钮提供 hover、active、focus-visible 和 disabled 状态。
- 按钮按下只做轻微缩放或表面变化，不改变点击事件和路由。
- `prefers-reduced-motion: reduce` 时取消位移、模糊、错峰和非必要高光。

## 8. 修改文件范围

### 8.1 允许调整

- `src/pages/HomePage.tsx`：仅调整展示结构、class、图标占位和可访问性属性；保留 props、回调和现有文案语义。
- `src/components/ProgressCard.tsx`：仅调整展示性 class、进度环表现和排版结构；保留百分比计算和 props。
- `src/components/AppShell.tsx`：如全局侧栏/内容容器需要适配，只调整展示层结构和 class；不改变导航目标。
- `src/styles/global.css`：接入视觉 token、首页布局、断点、主题、字体、图标和动效样式。

### 8.2 明确不修改

- `src/App.tsx` 的学习状态、数据加载和回调逻辑。
- `src/services/`、`src/types/` 中的学习、统计、词库和设置逻辑。
- `electron/`、preload、IPC、SQLite 和 Electron 数据通信。
- `resources/vocabulary_final.json`、`assets/icon.ico` 和词库内容。
- 快捷键语义、学习队列、数据库保存和路由行为。

## 9. 首页验收标准

### 9.1 数据和行为保持

- 首次加载、学习中、今日完成和再次开始四种状态的文案与 CTA 行为保持正确。
- 每日目标 35/50 切换仍调用现有回调并保存到现有 SQLite 设置。
- 当前词库信息、选择词库入口和学习进度数据与 v0.1.1 一致。
- 不新增首页业务状态、数据库字段、IPC 调用或统计计算。

### 9.2 视觉和窗口

- `920×620`：无横向溢出，主 CTA、当前词库、进度卡和目标选择可用。
- `1180×760`：主进度和目标区域层级清楚，首屏布局平衡。
- 宽屏/全屏：内容合理扩展，不集中在左上角，不无限放大字体。
- 深色/浅色主题：背景、卡片、按钮、进度、文字和焦点环可读。
- 字体三档缩放：不出现按钮遮挡、中文重叠或数字溢出。
- 无白边、白闪、内容断层、持续动画或系统默认焦点异常。

### 9.3 回归检查

- 页面导航、开始学习、继续学习、选择词库、目标按钮和快捷键回归通过。
- 关闭并重新打开应用后，首页仍正确读取原有学习进度和每日目标。
- UI 改造完成后，SQLite、词库 JSON、学习算法和 IPC 行为与改造前一致。
