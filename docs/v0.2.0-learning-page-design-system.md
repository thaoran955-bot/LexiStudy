# LexiStudy v0.2.0 学习页 UI Design System

> 阶段：Phase 4.2.1-A
> 状态：Design specification
> 适用版本：v0.2.0-alpha
> 设计方法：Token-first + Component State Matrix

## 1. 文档定位

学习页是 LexiStudy 的核心使用界面。本规范只定义学习页的视觉层、布局层、状态表达和动效规则，作为后续 UI 实现与审查的统一依据。

本规范继承项目现有的：

- Theme Token
- Typography Token
- Layout Token
- Radius Token
- Shadow Token
- Animation Token

学习页不建立独立的颜色、字体或间距体系。新增的 Learning Page Token 只承担语义映射，实际值必须来自现有全局 Token。

视觉基线采用克制、低干扰的桌面生产力工具方向：单词内容是唯一主焦点，卡片层级依靠表面、边框和有限阴影表达，不使用装饰性插画、强烈渐变或游戏化奖励元素。

## 2. v0.2.0 范围边界

### 2.1 允许调整

- 学习页 JSX 的展示层级、包裹层和 class 组织。
- 学习页的布局、尺寸、颜色、字体、圆角、阴影和间距。
- 显示答案、判断按钮、进度和反馈状态的视觉表达。
- 页面进入、答案显示、按钮反馈和下一词切换的轻量动效。
- 920×620、1180×760、宽屏和全屏窗口下的适配规则。
- 深色/浅色主题下的表现，以及 100%/125%/150%/175% 字体缩放下的可读性调整。

### 2.2 禁止调整

- 学习算法、掌握等级、错词复习和出题顺序。
- SQLite 数据结构、读写逻辑和保存时机。
- IPC、Electron 主进程、preload 或数据通信逻辑。
- 词库 JSON、词库格式、词库导入和词库身份规则。
- 学习记录、进度计算、快捷键语义和页面业务流程。
- 新增业务功能、新增学习阶段或新增数据字段。

## 3. 现有 Token 继承规则

### 3.1 Theme Token

学习页所有颜色必须通过以下现有语义 Token 使用：

| 用途 | Dark/Light 来源 Token | 使用原则 |
|---|---|---|
| 页面背景 | `--color-bg` | 学习页根背景，不直接写颜色值 |
| 卡片表面 | `--color-surface`、`--color-surface-elevated` | 用于 Word Card 与辅助面板层级 |
| 控件表面 | `--color-control`、`--color-control-hover` | 用于模式切换和次级按钮 |
| 主文字 | `--color-text` | 单词、主要标题和关键数值 |
| 次要文字 | `--color-text-muted` | 进度、辅助说明和答案提示 |
| 弱化文字 | `--color-text-subtle`、`--color-text-faint` | 编号、快捷键和低优先级说明 |
| 边框 | `--color-border`、`--color-border-strong` | 区分容器，不制造强烈分割线 |
| 主行动色 | `--color-brand`、`--color-brand-strong` | 只用于显示答案等当前主要操作 |
| 完成语义色 | `--color-success`、`--color-success-surface` | 认识、答案和完成状态 |
| 错误语义色 | `--color-danger`、`--color-danger-soft` | 不认识和错误反馈；不能只依赖颜色传达含义 |
| 焦点 | `--color-focus`、`--shadow-focus` | `focus-visible` 的统一表达 |
| 进度轨道 | `--color-track` | 进度未完成区域 |

Light Theme 必须使用现有 `data-theme="light"` 映射，不为学习页另建一套浅色变量。

### 3.2 Typography Token

学习页使用现有字体栈和缩放机制：

- 字体栈：`--font-family-sans`。
- 单词主文本：`--font-size-display`，保持 `--line-height-tight`。
- 中英文较长释义：`--font-size-word-meaning` 或 `--font-size-body`，保持可换行。
- 页面标题：`--font-size-page-title`。
- 进度和模式信息：`--font-size-label`。
- 辅助说明和快捷键：`--font-size-caption`。
- 100%、125%、150%、175% 由 `--font-scale` 统一驱动。

单词主文本可以随容器宽度限制，但不能通过裁切、强制单行或缩小到不可读来解决溢出。

### 3.3 Layout、Radius、Shadow、Animation Token

学习页的基础映射如下：

| 分类 | 继承 Token | 学习页用法 |
|---|---|---|
| 间距 | `--space-1` 至 `--space-16` | 组件内部、组件间和页面留白 |
| 控件圆角 | `--radius-control`、`--radius-button` | 模式按钮、行动按钮、快捷键胶囊 |
| 卡片圆角 | `--radius-card` | Word Card 主容器 |
| 进度圆角 | `--radius-pill` | 进度轨道和小型状态标识 |
| 卡片阴影 | `--shadow-card` | Word Card 的主要层级 |
| 面板阴影 | `--shadow-panel` | 页面辅助区域；不叠加多层阴影 |
| 焦点阴影 | `--shadow-focus` | 键盘焦点可见性 |
| 快速反馈 | `--duration-fast` | active、状态颜色和轻量反馈 |
| 标准过渡 | `--duration-standard` | 答案显示、页面和卡片进入 |
| 强调过渡 | `--duration-slow`、`--ease-emphasized` | 仅用于进度宽度等非阻塞反馈 |

## 4. Learning Page Token

Learning Page Token 是组件语义层，不替代全局 Token。实现时应优先使用以下语义别名；如果项目尚未实现别名，应直接映射到右侧的全局 Token。

### 4.1 内容与表面

| Learning Page Token | 映射 | 用途 |
|---|---|---|
| `--learning-page-background` | `--color-bg` | 学习页背景 |
| `--learning-card-background` | `--color-surface-elevated` | Word Card 默认表面 |
| `--learning-card-border` | `--color-border-strong` | Word Card 边框 |
| `--learning-card-shadow` | `--shadow-card` | Word Card 层级 |
| `--learning-word-color` | `--color-text` | 英文单词或中文提示 |
| `--learning-meta-color` | `--color-text-subtle` | 单词编号、模式标签 |
| `--learning-helper-color` | `--color-text-muted` | 辅助提示、进度和说明 |
| `--learning-answer-color` | `--color-success` | 已显示的答案 |
| `--learning-focus-ring` | `--shadow-focus` | 键盘焦点 |

### 4.2 操作与反馈

| Learning Page Token | 映射 | 用途 |
|---|---|---|
| `--learning-primary-background` | `--color-brand` | 显示答案按钮 |
| `--learning-primary-hover` | `--color-brand-strong` | 主按钮 hover 或强调态 |
| `--learning-primary-text` | `--color-brand-contrast` | 主按钮文字 |
| `--learning-known-background` | `--color-success-surface` | 认识按钮的语义背景或 feedback |
| `--learning-known-color` | `--color-success` | 认识的文字或图标 |
| `--learning-unknown-background` | `--color-danger-soft` | 不认识按钮的语义背景或 feedback |
| `--learning-unknown-color` | `--color-danger` | 不认识的文字或图标 |
| `--learning-progress-track` | `--color-track` | 进度未完成部分 |
| `--learning-progress-fill` | `--color-success` | 进度已完成部分 |
| `--learning-disabled-opacity` | `0.45` | 不满足前置状态时的统一弱化程度 |

### 4.3 尺寸与节奏

| Learning Page Token | 建议值 | 说明 |
|---|---|---|
| `--learning-content-max-width` | `min(100%, 1080px)` | 限制学习内容宽度，避免全屏过度拉伸 |
| `--learning-word-max-width` | `min(100%, 760px)` | 限制主文本阅读宽度 |
| `--learning-card-padding` | `clamp(var(--space-6), 4vw, var(--space-12))` | 随窗口变化的卡片内边距 |
| `--learning-section-gap` | `clamp(var(--space-3), 2vw, var(--space-6))` | 页面主要区域之间的间距 |
| `--learning-action-gap` | `var(--space-3)` | 判断按钮之间的间距 |
| `--learning-answer-min-height` | `calc(24px * var(--font-scale))` | 答案隐藏时预留稳定空间 |
| `--learning-card-radius` | `var(--radius-card)` | 主卡片圆角 |
| `--learning-control-radius` | `var(--radius-control)` | 所有操作控件圆角 |
| `--learning-transition` | `var(--duration-standard) var(--ease-standard)` | 常规视觉状态过渡 |

以上尺寸是 UI 规范建议，不改变业务数据或组件行为。实现时应优先采用 `clamp()`、`minmax(0, 1fr)` 和自然换行，避免固定尺寸造成窗口溢出。

## 5. 学习页信息层级

从高到低的视觉优先级固定为：

1. 当前单词或当前中文提示。
2. 当前阶段可执行的操作。
3. 答案内容和学习反馈。
4. 当前模式与进度。
5. 单词编号、快捷键提示和本地保存说明。

页面结构建议保持为以下展示层级，不新增业务模块：

```text
study-page
├── study-header
│   ├── 页面标题
│   └── 学习模式 + 进度指示
├── word-stage
│   └── word-card
│       ├── 单词编号
│       ├── 当前提示
│       ├── 答案区域
│       └── 显示答案操作
├── answer-actions
│   ├── 不认识
│   └── 认识
└── study-note
```

该结构是展示层级建议，不代表新增 React 业务组件。组件拆分必须保持现有 props、回调、状态和数据流不变。

## 6. 组件规范与状态矩阵

### 6.1 Word Card

**职责：** 承载当前学习内容，是页面唯一的视觉主焦点。

**结构规则：**

- 单词编号是辅助信息，不能压过单词正文。
- 英文单词使用主文字色和显示字号。
- 中译英模式下中文提示使用可读的行高，并允许多行换行。
- 答案区域在隐藏状态下保留最小高度，显示答案后不推动按钮发生大幅位移。
- 卡片宽度随内容区扩展，但必须受 `--learning-content-max-width` 限制。
- 卡片不叠加装饰性徽章、奖励、等级或新业务提示。

| 状态 | 视觉表现 | 可交互性 | 备注 |
|---|---|---|---|
| 默认 / 看题 | `--learning-card-background`、`--learning-card-border`、`--learning-card-shadow` | 显示答案可用；判断按钮不可用 | 保持注意力集中在提示内容 |
| 答案隐藏 | 答案区显示低对比度提示文字并保留高度 | 不改变数据状态 | 不使用闪烁或占位骨架 |
| 答案已显示 | 答案使用 `--learning-answer-color`，内容平滑出现 | 判断按钮可用；显示答案按钮禁用 | 视觉上明确进入判断阶段 |
| 状态反馈 | 卡片边框或内层提示短暂使用认识/不认识语义色 | 不阻塞下一次操作 | 仅表达已有结果，不新增反馈业务 |
| 完成 | 使用现有完成态容器和成功语义 | 现有完成页操作保持不变 | 不增加奖励动画或新统计 |
| Focus-visible | 使用统一焦点环 | 键盘操作可见 | 不改变卡片布局尺寸 |

### 6.2 Action Button

包括“显示答案”“认识”“不认识”以及模式切换控件。按钮文字、快捷键和颜色必须共同表达含义，不能只依赖颜色。

| 状态 | 视觉表现 | 规则 |
|---|---|---|
| 默认 | 清晰的文字、稳定的控件尺寸和统一圆角 | 显示答案是看题阶段的主操作；判断按钮保持次级层级 |
| Hover | 背景、边框或文字轻微变化 | 使用 `--duration-fast`，不改变位置和尺寸 |
| Active / Pressed | 轻微颜色加深或 `transform` 压缩反馈 | 不触发额外业务动作，不产生跳动 |
| Focus-visible | `--color-focus` + `--shadow-focus` | 鼠标点击不强制显示焦点，键盘焦点必须可见 |
| Disabled | `opacity: var(--learning-disabled-opacity)`、禁用光标 | 禁用时保留原位置和尺寸，避免布局重排 |
| Reduced motion | 移除 transform 和非必要过渡 | 仍保持颜色与文字状态反馈 |

按钮层级固定为：

1. **Primary：显示答案**——答案隐藏时唯一突出操作。
2. **Judgment：认识 / 不认识**——答案显示后成为主要判断区域，两个按钮保持同等权重。
3. **Tertiary：模式切换和辅助操作**——可见但不抢占单词卡焦点。

### 6.3 Progress Indicator

进度指示只反映现有学习进度，不创建新的指标或计算方式。

可采用现有文字计数和轨道组合：

- 文字计数：`当前序号 / 本轮总数`，使用 `--font-size-label` 或相邻层级。
- 轨道：背景使用 `--learning-progress-track`，完成部分使用 `--learning-progress-fill`。
- 轨道高度保持紧凑，圆角使用 `--radius-pill`。
- 宽度随容器变化，不使用固定像素宽度。
- 进度变化允许使用 `--duration-slow` 的宽度过渡，但不延迟数据更新或下一词出现。

| 状态 | 视觉表现 | 规则 |
|---|---|---|
| 默认 | 显示当前序号和静态轨道 | 与单词卡保持辅助层级 |
| 更新中 | 填充宽度过渡到新位置 | 只做视觉过渡，不阻塞交互 |
| 接近完成 | 继续使用同一套颜色和尺寸 | 不新增警告或倒计时 |
| 完成 | 进入现有完成页面状态 | 不通过闪烁或大型庆祝动画强调 |
| Reduced motion | 立即更新填充宽度 | 文本进度仍必须同步 |

### 6.4 Feedback State

Feedback State 只呈现用户已经做出的判断，不引入新的分数、奖励、音效或流程。

| 状态 | 语义 | 视觉表达 | 使用边界 |
|---|---|---|---|
| Neutral | 尚未判断 | 默认文字和边框 Token | 不使用成功/错误色 |
| Answer Revealed | 已显示答案，等待判断 | 答案使用成功语义色；判断区启用 | 不等同于答对 |
| Known | 用户选择认识 | 使用 `--color-success` / `--color-success-surface` | 文案或图标必须同时表达含义 |
| Unknown | 用户选择不认识 | 使用 `--color-danger` / `--color-danger-soft` | 不使用强烈红色闪烁 |
| Transition | 结果已接收，进入下一词 | 短暂 opacity/transform 过渡 | 不改变记录保存时机 |
| Complete | 本轮完成 | 使用现有完成页视觉语言 | 不扩展为新奖励系统 |

反馈颜色不能成为唯一信息通道。至少同时使用文字、位置、图标或边框差异中的一种辅助表达。

## 7. 学习流程状态说明

### 7.1 看题

- Word Card 显示当前单词或中文提示。
- 答案区域保留稳定的最小高度，并显示“准备好后查看答案”等辅助提示。
- “显示答案”按钮可用且为当前 Primary 操作。
- “认识”和“不认识”保持禁用，不能在答案隐藏时提交判断。

### 7.2 显示答案

- 答案在原位置出现，不使卡片或判断按钮大幅跳动。
- 答案使用成功语义色或现有答案 Token，突出但不超过当前单词正文。
- “显示答案”进入禁用状态。
- “认识”和“不认识”同时进入可用状态，并保持等宽、等权重。

### 7.3 判断

- 用户通过鼠标或现有快捷键完成判断。
- 两种输入方式必须得到一致的视觉结果。
- 反馈可以短暂表现为颜色、边框或轻微透明度变化。
- 不显示新的确认弹窗，不新增阻塞步骤。

### 7.4 下一词

- 当前反馈结束后进入已有的下一词状态。
- 清除上一词答案和反馈视觉状态。
- 进度文字与轨道同步更新。
- 新词成为唯一视觉焦点，操作按钮回到对应的前置状态。
- 动画不能改变学习记录、索引推进或 SQLite 保存时机。

## 8. 响应式规则

### 8.1 920×620：紧凑窗口

- 学习页允许自然纵向滚动，但禁止横向溢出。
- 页头允许换行：标题、模式切换和进度计数不强行挤在同一行。
- Word Card 使用较小的 `--learning-card-padding`，但保留足够的阅读呼吸空间。
- 单词卡高度由内容和可用视口共同决定，不能使用导致底部操作被遮挡的固定最小高度。
- 判断按钮保持两列等宽；如果实际宽度不足，按钮文字不得被裁切。
- 长中文释义必须自然换行，不能出现横向滚动。
- 100% 到 175% 字体缩放下，按钮和计数可以换行，但不改变操作顺序。

### 8.2 1180×760：标准窗口

- 学习内容在主区域居中，最大宽度由 `--learning-content-max-width` 控制。
- Word Card 获得充足内边距，单词正文保持明显主焦点。
- 页头、单词卡、判断区和辅助说明形成连续的垂直节奏。
- 进度信息与模式切换可以保持同一行，但不能与单词内容竞争视觉焦点。
- 页面不得因为可用宽度增加而无限放大单词字号或卡片阴影。

### 8.3 宽屏与全屏

- 内容区域继续使用最大宽度限制，额外空间转化为左右留白，而不是拉伸文字行长。
- 单词卡可以在最大范围内扩展，但主文本保持 `--learning-word-max-width`。
- 纵向空间增加时，优先增加卡片周围的呼吸空间，不新增信息模块。
- 阴影保持克制，避免全屏下出现大面积浮夸的光晕。
- 任何窗口尺寸下都不得出现按钮被遮挡、快捷键说明溢出或横向滚动条。

### 8.4 主题与字体缩放兼容

- Dark / Light 主题只改变 Token 映射，不改变组件结构、交互顺序和状态含义。
- 主题切换后，主文字、答案、成功/错误反馈和焦点状态必须保持可辨识。
- 字体缩放使用现有 `data-font-scale` 机制。
- 175% 下优先允许布局换行和卡片增高，不通过截断文字或强制固定高度解决问题。
- reduced-motion 只减少动画，不删除状态反馈、焦点环和进度信息。

## 9. 动效规范

### 9.1 动画时间

| 场景 | Token | 规范 |
|---|---|---|
| 按钮 hover / active | `--duration-fast` | 快速、明确，不制造延迟感 |
| 答案出现 | `--duration-standard` | 只使用 opacity 和轻微 transform |
| 下一词切换 | `--duration-standard` | 新旧内容切换自然，不改变卡片尺寸 |
| 进度更新 | `--duration-slow` | 只过渡轨道宽度，不延迟实际状态 |
| 页面进入 | `--duration-standard` + `--ease-emphasized` | 轻量进入，不遮挡单词内容 |

### 9.2 使用场景

允许的动效仅用于：

- 页面首次进入时建立层级。
- 答案从隐藏到显示时提供状态确认。
- 按钮 hover、active 和 focus-visible 提供操作反馈。
- 进入下一词时避免突然切换造成的视觉断裂。
- 进度轨道反映已有进度变化。

禁止使用：

- 循环闪烁、持续呼吸或自动播放装饰。
- 延迟按钮可用、答案显示或下一词进入。
- 通过震动、弹跳或大幅缩放制造游戏化刺激。
- 影响滚动、键盘快捷键或鼠标操作的动画。

### 9.3 reduced-motion

在 `prefers-reduced-motion: reduce` 下：

- 取消页面进入、答案出现和下一词切换的 transform 动画。
- 将过渡缩短为即时变化或仅保留极短颜色变化。
- 保留文字、边框、按钮启用/禁用、焦点环和进度更新。
- 不改变学习流程、数据写入或快捷键语义。

### 10.2 变更规则

每次学习页 UI 变更前必须：

1. 先确认变更属于 UI/UX 范围。
2. 先更新本规范中的 Token、组件状态矩阵或响应式规则。
3. 明确 Dark / Light、字体缩放和 reduced-motion 的表现。
4. 明确不会改变 props、回调、数据流、SQLite、IPC 或学习算法。
5. 完成 920×620、1180×760、全屏和键盘焦点检查。

### 10.3 规范优先级

出现冲突时按以下顺序处理：

1. 项目范围限制与业务行为不变原则。
2. 全局 Theme、Typography、Layout Token。
3. 本学习页 Design System 的语义 Token 与状态矩阵。
4. 单个页面或组件的局部样式。

不应在页面 CSS 中直接新增与全局语义重复的颜色值、字号值、圆角值或阴影值。确有必要时，先在本规范中说明语义用途，再映射到既有 Token。

## 11. 验收标准

- 看题、显示答案、判断、下一词四个阶段的视觉状态清晰且顺序不变。
- Word Card 始终是页面主焦点，辅助信息不会抢占注意力。
- 鼠标和现有键盘操作的视觉反馈一致。
- 默认、hover、active、focus-visible、disabled 状态完整。
- Dark / Light 主题下层级、对比度和语义一致。
- 100%/125%/150%/175% 字体缩放下无文字裁切或横向溢出。
- 920×620、1180×760、宽屏和全屏下无操作区遮挡。
- reduced-motion 下仍能完整识别状态与完成操作。
- 未修改学习算法、SQLite、IPC、词库和数据流程。
