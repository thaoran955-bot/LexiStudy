# LexiStudy v0.2.0 学习页 UI 设计任务书

## 0. 文档定位

本任务书用于指导 LexiStudy v0.2.0 学习页的 UI/UX 优化实现。

本阶段只分析和设计表现层，不直接修改代码。学习页是应用的核心使用页面，所有视觉调整都必须服务于“长时间、低干扰、可持续”的每日学习场景。

必须保持：

- 一次只显示一个单词。
- 英译中和中译英两种现有模式。
- 显示答案后由用户选择“认识”或“不认识”。
- Space、Left Arrow、Right Arrow、Esc 的现有快捷键语义。
- 现有路由、学习进度、记录保存和页面完成状态。

## 1. 学习页定位

### 1.1 核心职责

学习页承担用户每天最主要的背词操作：

```text
看到一个提示
→ 独立回忆
→ 查看答案
→ 判断认识程度
→ 获得即时反馈
→ 进入下一个单词
```

学习页不是统计仪表盘，也不是词库管理页面。它应当围绕当前单词建立单一视觉焦点，减少与答题无关的信息、装饰和操作干扰。

### 1.2 长期学习场景

典型用户会在固定桌面窗口中每天使用数分钟到数十分钟，因此页面需要：

- 降低重复操作的视觉疲劳。
- 让“提示—答案—判断”的节奏稳定、可预期。
- 使英文单词、中文释义和按钮在不同字号下始终清晰。
- 在窗口较小、全屏或字体放大时保持内容完整可用。
- 让用户不用寻找当前状态：是否已显示答案、当前第几个词、下一步能做什么都应明确。

### 1.3 视觉原则

- 单词卡是页面最高视觉层级。
- 显示答案是当前回合的主要操作。
- “认识/不认识”是答案出现后的判断操作，不应在答案未显示时抢占注意力。
- 模式、计数和辅助说明保持可见但低于单词卡。
- 动效只用于状态确认，不制造游戏化刺激或延迟操作。

## 2. 当前学习页分析

### 2.1 当前组件结构

当前学习页由 `src/pages/StudyPage.tsx` 单页组件完成，未拆分独立业务子组件。

组件接收的现有数据和回调包括：

- `vocabulary`：当前学习词汇序列。
- `startIndex`：恢复学习时的起始位置。
- `mode`：英译中或中译英。
- `onModeChange`：保存学习模式变化。
- `onIndexChange`：保存当前学习进度。
- `onAnswer`：提交认识/不认识记录。

组件内部现有展示状态：

- `index`：当前单词索引。
- `showAnswer`：当前单词是否已经显示答案。
- `entry`：当前展示的词库条目。

组件内部现有行为：

- 根据 `startIndex` 恢复当前学习位置。
- 使用 `getFrontText` 和 `getAnswerText` 根据模式决定正面提示和答案内容。
- 答题后提交 `LearningRecord`，移动到下一个索引，并同步保存进度。
- 使用捕获阶段的 `keydown` 监听响应快捷键。
- 词汇耗尽后显示“今日目标已完成”和“再学一轮”入口。

### 2.2 当前布局

当前页面顺序为：

```text
study-page / page-stack
├── compact-header
│   ├── 学习中 / 新词练习
│   └── 英译中、中译英、当前计数
├── word-card
│   ├── 单词编号
│   ├── 正面提示：英文单词或中文释义
│   ├── 未显示答案提示或中文/英文答案
│   └── 显示答案按钮
├── answer-actions
│   ├── 不认识
│   └── 认识
└── phase-note
    └── 本地保存说明
```

### 2.3 当前视觉问题

#### 单词卡比例

- `.word-card` 当前使用固定的 `min-height` 和较大的内边距，矮窗口下可能产生无效留白。
- 宽窗口下单词卡可以适度扩展，但不能让字号和圆环式装饰压过单词本身。
- 中译英模式的中文释义可能较长，需要保证自然换行，不让内容撑破卡片。

#### 操作层级

- 显示答案、认识、不认识三个阶段目前主要通过 disabled 状态区分，状态含义仍可进一步增强。
- 答案出现后，页面应更明确地提示用户进入判断阶段。
- “认识”和“不认识”按钮需要保持同等可见性，同时使用颜色和文字语义区分，不依赖颜色单独传达含义。

#### 顶部信息密度

- 模式切换、当前计数和标题集中在同一行，紧凑窗口下需要明确换行优先级。
- 计数器应保持可见，但不应与模式按钮争夺单词卡的视觉焦点。

#### 反馈表现

- 当前主要反馈是答案文本出现和进入下一个单词，状态过渡可以更连贯。
- 答题后若增加切换动画，必须避免让用户误以为记录尚未保存或重复提交。
- 完成状态需要与普通答题状态保持明显差异，但不应加入新的奖励或游戏化机制。

#### 视觉疲劳风险

- 长时间使用时，过强的高亮色、过大的卡片阴影或持续动画都会增加干扰。
- 单词卡、答案按钮和答题按钮需要形成稳定节奏，避免每次状态变化都产生明显跳动。
- 辅助保存说明应保持低强调，不能与当前单词和答题操作竞争。

### 2.4 当前交互流程

当前交互流程如下：

1. 页面读取 `startIndex` 和当前 `mode`。
2. 显示当前单词或中文释义。
3. 用户点击“显示答案”或按 Space。
4. 显示答案，启用“认识”和“不认识”。
5. 用户点击按钮，或按 Right Arrow / Left Arrow。
6. 调用 `onAnswer` 保存本次记录。
7. 清除答案状态，进入下一个单词。
8. 同步 `onIndexChange` 保存当前进度。
9. 用户按 Esc 返回首页。
10. 队列结束后显示完成状态和“再学一轮”。

## 3. 用户学习流程分析

### 3.1 流程总览

```text
进入学习页
    ↓
读取并显示当前单词
    ↓
用户独立回忆
    ↓
Space / 点击“显示答案”
    ↓
显示中文释义或英文答案
    ↓
用户判断：认识 / 不认识
    ↓
保存学习记录并更新进度
    ↓
进入下一个单词
    ↓
队列结束后显示完成状态
```

### 3.2 进入学习页

进入页面后应立即显示：

- 当前学习模式。
- 当前进度，例如 `12 / 35`。
- 一个可独立阅读的单词提示。
- 用户下一步可以显示答案的明确提示。

不应在单词出现前播放阻塞式动画、弹窗或额外确认。

### 3.3 单词学习阶段

单词学习阶段的核心是回忆，不是阅读大量界面信息：

- 单词或中文释义位于卡片视觉中心。
- 单词编号是辅助信息，不应高于单词正文。
- 未显示答案时，答案区域保留稳定空间，避免显示答案后卡片整体跳动。
- 长文本允许换行，不能裁剪关键内容。

### 3.4 用户操作阶段

操作顺序应保持单向清晰：

- 答案未显示时，只突出“显示答案”。
- 答案已显示时，明确突出“认识/不认识”判断。
- 未满足前置条件的按钮可以 disabled，但不能消失或改变布局位置。
- 鼠标与键盘操作应共享同一套视觉状态。

### 3.5 反馈阶段

反馈只需要让用户确认三件事：

1. 本次判断已被接受。
2. 当前记录已继续进入学习流程。
3. 下一个单词已经出现。

可使用短暂的颜色、透明度或位移过渡，但不能改变保存时机、答题结果或队列顺序。

### 3.6 下一词阶段

进入下一词时：

- 旧答案不能残留。
- 新单词应立即成为唯一主焦点。
- 计数器应与实际索引同步。
- 不应出现重复提交、按钮状态滞后或快捷键失效。

## 4. UI/UX 优化方向

### 4.1 单词展示区域

- 使用响应式卡片宽度和高度，避免固定尺寸占满矮窗口。
- 英文单词使用清晰的主字号和紧凑行高。
- 中文释义或中译英正面使用更适合中文阅读的行高，并允许多行。
- 保持答案区域最小高度，显示答案后不推动按钮大幅移动。
- 通过 `--font-scale` 支持 100%、125%、150%、175% 四档字号。
- 长单词、长释义和高字号下必须优先保证完整显示。

### 4.2 操作区域

- 显示答案按钮作为答案未显示阶段的 primary action。
- 认识/不认识按钮在答案出现后成为主要判断区域。
- 两个判断按钮保持相近宽度和稳定位置。
- Space、Left Arrow、Right Arrow 的提示可以保留在按钮附近，但不能喧宾夺主。
- hover、active、focus-visible 和 disabled 状态保持一致，不新增操作含义。

### 4.3 信息层级

建议层级：

```text
单词/释义正文
    ↓
当前操作按钮
    ↓
模式与进度计数
    ↓
编号、保存说明和辅助提示
```

- 标题“新词练习”用于定位页面，不应大于单词正文的视觉重点。
- 模式按钮和计数器作为导航辅助信息，保持紧凑。
- 保存说明使用低对比文字，不使用持续高亮。

### 4.4 学习反馈

- 显示答案时使用短暂、低幅度的透明度或位移过渡。
- 答题后按钮可以使用轻微 active 状态和颜色变化。
- 进入下一词时只动画 `opacity` 和 `transform`，不动画布局尺寸。
- `prefers-reduced-motion: reduce` 时取消非必要过渡和错峰动画。
- 认识和不认识的颜色语义应与现有成功/错误 Token 一致，但不能只用颜色区分。

### 4.5 页面布局

#### 标准窗口

- 顶部标题、模式、计数器保持清晰的一行布局。
- 单词卡作为页面主区域，操作按钮紧跟其后。
- 页面左右留白使用 Layout Token，避免内容贴边。

#### 紧凑窗口

- 标题、模式按钮和计数器允许自然换行。
- 单词卡减少无效上下内边距，但保持足够的阅读空间。
- 答题按钮保持完整点击区域，不因窗口变窄而压缩文字。
- 页面允许纵向滚动，不能产生横向溢出。

#### 宽屏和全屏

- 单词卡适度扩展宽度，不无限放大单词字号。
- 内容保持合理最大宽度，避免单词与操作区域过度分散。
- 纵向空间增加时，优先增加呼吸空间，不新增信息模块。

### 4.6 深色/浅色主题

- 深色模式使用主进度表面和低对比边界，减少长时间使用的刺眼对比。
- 浅色模式保持完整的背景、卡片、文字、边框和状态 Token 映射。
- 主行动色用于显示答案和当前 active 状态。
- 成功/错误语义用于认识/不认识反馈，不将所有按钮统一染成状态色。
- 主题变化不改变单词内容、按钮位置、交互顺序或快捷键语义。

## 5. v0.2.0 范围限制

### 5.1 允许修改

- 学习页 JSX 的展示性 class、布局包装和可访问性属性。
- 学习页 CSS 布局、颜色、字体、圆角、阴影和间距。
- 学习页的轻量入场、状态过渡和按钮反馈动画。
- 深色/浅色主题下的学习页表现层适配。
- 紧凑窗口、标准窗口、宽屏和全屏下的布局规则。

### 5.2 禁止修改

- 不新增学习功能、复习功能、统计功能或用户设置功能。
- 不修改学习算法、学习队列、掌握等级或错词逻辑。
- 不修改 SQLite 表结构、字段、保存时机或数据模型。
- 不修改 IPC、preload、Electron 数据通信或文件访问逻辑。
- 不修改词库 JSON、词库格式、词库内容或词库导入逻辑。
- 不修改学习数据流程、进度计算、答题记录和路由语义。
- 不改变 Space、Left Arrow、Right Arrow、Esc 的快捷键语义。
- 不增加新的业务组件或新的业务状态。

### 5.3 实现前置检查

学习页 UI 实现前必须确认：

- `StudyPage` 的 props、回调和状态判断保持原样。
- `getFrontText`、`getAnswerText` 和快捷键处理逻辑不被触碰。
- 答案显示前后按钮 disabled 状态保持一致。
- 现有学习记录和进度恢复流程不受影响。
- 设计变更可以通过现有测试和构建流程验证。

## 6. 设计验收标准

- 用户进入学习页后能立即识别当前单词、模式、进度和下一步操作。
- 单词卡在英译中、中译英和长文本场景下均可读、不溢出。
- 显示答案、认识、不认识的状态变化自然且不阻塞操作。
- 鼠标操作与快捷键操作的视觉结果一致。
- `920×620`、`1180×760`、宽屏和全屏无横向溢出或内容遮挡。
- 深色和浅色主题均保持层级、对比度和语义一致。
- 100%、125%、150%、175% 字体缩放不造成按钮、释义和计数器重叠。
- reduced-motion 环境下页面仍然完整可用。
- 学习算法、SQLite、IPC、词库和数据流程没有任何变化。
