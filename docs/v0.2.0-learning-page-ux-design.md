# LexiStudy v0.2.0 学习页 UX/UI 方案

## 文档定位

- 版本：`v0.2.0-alpha`
- 分支：`feature/v0.2.0-learning-page`
- 范围：`UI/UX Enhancement Only`
- 设计对象：现有 `StudyPage` 学习流程
- 状态：UX/UI 方案设计文档

本方案基于以下文档，并继承其中的 Token、布局、主题和动效约束：

- `docs/v0.2.0-learning-page-design-task.md`
- `docs/v0.2.0-learning-page-design-system.md`
- `docs/v0.2.0-visual-system-design.md`
- `docs/v0.2.0-ui-design-spec.md`

本方案使用 UI-UX Pro Max 的分析优先级：

1. 无障碍与键盘可用性。
2. 交互反馈与可预测状态。
3. 布局稳定性，避免答案出现造成内容跳动。
4. 响应式与长文本可读性。
5. 与现有 Token 和组件状态矩阵保持一致。

UI-UX Pro Max 的通用检索结果仅作为 UX 规则参考。若通用推荐与 LexiStudy 现有设计体系冲突，以项目现有 Design System 和本项目范围约束为准；本方案不引入新的颜色、字体或视觉风格。

## 1. 学习页产品定位

### 1.1 在 LexiStudy 中的作用

学习页是 LexiStudy 的核心使用页面，负责承载用户每日最主要的单词学习动作。它不是统计仪表盘、词库管理页或内容浏览页，而是一个围绕当前单词建立单一视觉焦点的短循环学习界面。

页面必须保持现有业务语义：

- 一次只展示一个单词。
- 保持英译中与中译英两种现有模式。
- 用户先独立回忆，再查看答案。
- 显示答案后由用户选择“认识”或“不认识”。
- 保持 Space、Left Arrow、Right Arrow、Esc 的现有快捷键语义。
- 保持现有路由、学习进度、记录保存和完成状态。

### 1.2 用户长期使用场景

典型用户在固定 Windows 桌面窗口中每天使用数分钟到数十分钟。用户会重复执行相同的“看题—揭示—判断—下一词”循环，因此页面重点不是一次性的视觉惊喜，而是：

- 状态变化容易预测。
- 下一步操作无需寻找。
- 单词、释义和按钮在长时间使用中保持清晰。
- 窗口缩放、字体放大和长文本不会破坏布局。
- 动效只确认状态，不延迟学习节奏。

### 1.3 设计目标

本阶段目标是建立“低干扰、稳定节奏、单词优先”的学习体验：

1. 让用户进入页面后立即识别当前提示、模式、进度和下一步。
2. 让答案显示前后的操作层级明确，不依赖 disabled 状态单独传达含义。
3. 让 Word Card 在英译中、中译英、长中文释义和字体缩放场景下稳定可读。
4. 让鼠标和键盘操作共享同一套状态视觉。
5. 通过保留空间、短动效和清晰反馈降低重复操作的认知负担。

## 2. 用户学习流程分析

### 2.1 当前流程

```text
看题
  ↓
显示答案
  ↓
用户判断：认识 / 不认识
  ↓
进入下一词
```

在现有实现中，`StudyPage` 通过 `index`、`showAnswer` 和当前 `entry` 控制展示状态，并通过现有回调保存答题记录与学习进度。本方案只优化这些状态的表现层，不改变其含义和调用时机。

### 2.2 主要 UX 风险

#### 认知负担

- 用户需要在每一轮判断当前是否已经显示答案。
- 模式、进度、单词编号和辅助说明可能与单词正文竞争注意力。
- 判断按钮如果只用颜色或 disabled 表达状态，用户需要额外推断下一步。

#### 节奏中断

- 答案出现后如果改变卡片高度，会推动按钮位置，破坏重复操作节奏。
- 答题反馈过慢会让用户误以为记录尚未保存。
- 下一词切换残留旧答案，会造成重复确认或误答风险。

#### 反馈不足

- 用户需要确认本次判断已经被接受。
- 用户需要确认当前记录已继续进入学习流程。
- 用户需要立即识别新单词已经成为当前唯一焦点。

### 2.3 优化后的学习节奏

```text
提示阶段
  → 用户独立回忆
  → Space / 点击“显示答案”
答案阶段
  → 读取答案并判断
  → Left Arrow / Right Arrow / 点击判断按钮
反馈与切换
  → 短暂确认
  → 清除旧答案
  → 新单词立即成为主焦点
```

优化重点：

- 降低认知负担：用固定布局、明确阶段文案和可见但弱化的禁用按钮表达状态。
- 提升学习节奏：保留答案区空间，保持判断按钮位置稳定，键盘和鼠标反馈一致。
- 增强反馈感：使用短暂颜色、透明度或位移确认状态，但不改变保存时机、答题结果或队列顺序。

## 3. 页面信息架构

页面采用“Header → Word Stage → Word Card → Action → Feedback”的结构。区域之间通过间距、对齐、字号和语义色建立层级，不通过增加面板数量制造信息密度。

```text
study-page
├── Header
│   ├── 学习中 / 新词练习
│   ├── 英译中 / 中译英
│   └── 12 / 35
├── Word Stage
│   └── 当前学习进度的低强调上下文
├── Word Card
│   ├── WORD 0012
│   ├── 正面提示
│   ├── 答案保留区
│   └── 显示答案
├── Action
│   ├── 不认识
│   └── 认识
└── Feedback
    └── 阶段提示 / 本地保存说明
```

### 3.1 Header 区域

内容：

- 页面定位：`学习中`、`新词练习`。
- 模式切换：`英译中`、`中译英`。
- 当前进度：例如 `12 / 35`。

视觉优先级低于 Word Card，但必须在进入页面后立即可见。标准窗口保持一行；紧凑窗口允许换行，模式和进度不能因空间不足而消失。

### 3.2 Word Stage 区域

Word Stage 是学习内容所在的主舞台容器，负责提供页面中心的阅读空间和纵向呼吸感。它不新增统计、计时器、激励文案或业务状态。

视觉优先级：

```text
Word Card > 当前操作 > Header > Feedback 辅助说明
```

### 3.3 Word Card 区域

Word Card 是页面最高视觉层级，承载当前单词、正面提示、答案保留区和“显示答案”按钮。卡片依靠表面层、边框和有限阴影表达层级，不使用装饰性插画、强烈渐变或持续光效。

### 3.4 Action 区域

Action 区域位于 Word Card 下方，固定承载“不认识”和“认识”。两个按钮等宽、相邻、可见，答案未显示时 disabled，答案显示后同时启用。

Action 不放在页面底部固定栏中，避免在紧凑窗口、字体放大或纵向滚动场景下遮挡内容。

### 3.5 Feedback 区域

Feedback 只承担阶段确认和低优先级辅助说明：

- 提示阶段：准备好后查看答案。
- 答案阶段：请选择你的判断。
- 学习页底部：本地保存说明。

Feedback 不使用持续高亮，不新增 toast、奖励、连击或游戏化机制。

## 4. Word Card UX 设计

### 4.1 单词展示

- 英译中模式下，英文单词作为主提示，使用 `--font-size-display` 和 `--line-height-tight`。
- 中译英模式下，中文释义作为主提示，使用适合中文阅读的行高并允许自然换行。
- 单词编号 `WORD 0012` 作为辅助信息，使用 muted/subtle 文本 Token，不高于单词正文。
- 正文阅读宽度限制在合理最大值，避免宽屏下行长过长。
- 超长单词不得用强制单行、裁剪或隐藏溢出来处理。

### 4.2 音标展示

音标属于单词辅助信息，若当前已有词条数据能够提供音标，则设计上放置在英文单词下方、答案区上方，使用低于单词正文的字号和 muted 文本颜色。

v0.2.0 不新增音标字段、词库格式、数据读取逻辑或业务组件。如果当前词条没有音标数据，则不显示空占位、不生成假数据，也不改变卡片垂直节奏。

### 4.3 答案隐藏状态

答案未显示时：

- 正面提示保持视觉中心。
- 答案区域保留稳定的最小高度。
- 显示答案按钮是当前唯一 primary action。
- “认识 / 不认识”保持可见但 disabled，不改变位置。
- 辅助文案为“准备好后查看答案”。

### 4.4 答案显示状态

答案显示后：

- 答案立即可读，使用 `--color-success` 或对应 Learning Page Token。
- Word Card 尺寸不因答案内容改变而发生跳动。
- 显示答案按钮保持原位但 disabled。
- “认识 / 不认识”同时成为主要判断操作。
- 辅助文案切换为“请选择你的判断”。
- 答案文本必须与中文/英文内容保持完整换行，不裁剪关键内容。

### 4.5 例句展示

例句若已存在于当前展示数据中，可作为答案之后的低优先级辅助内容，放置在答案下方，使用 body/meaning 级别文字和更宽松的行高；例句不能压过单词、答案或判断按钮。

当前 v0.2.0 只定义展示层级，不新增例句数据字段、词库内容、数据流或新的学习步骤。没有现有例句时不显示空模块，不使用伪造示例填充卡片。

### 4.6 长文本适配

- 中文释义、英文答案和例句允许自然换行。
- 内容区使用 `min-width: 0` 和合理的 `max-width`。
- 答案区域保留稳定最小高度，但允许在必要时自然增高。
- `overflow: hidden` 不得用于裁剪关键学习内容。
- 100%、125%、150%、175% 字体缩放下，优先增加页面高度或启用纵向滚动，不压缩到不可读。
- 文本行长尽量限制在约 65–75 个字符的舒适范围内。

### 4.7 Word Card 状态矩阵

| 状态 | 内容 | 视觉表达 | 允许的交互 |
|---|---|---|---|
| Default | 正面提示、答案保留区 | 默认卡片表面，单词为最高层级 | 显示答案 |
| Answer hidden | 答案未显示 | 辅助提示低强调，判断按钮 disabled | Space / 显示答案 |
| Answer revealed | 答案可见 | 答案使用成功语义色，卡片不跳动 | 判断按钮 |
| Transition | 切换到下一词 | 仅 `opacity` + `transform`，不改变布局尺寸 | 不阻塞下一词 |
| Complete | 队列结束 | 沿用现有完成面板和再学一轮入口 | 现有完成流程 |

## 5. 操作区域设计

### 5.1 显示答案按钮

显示答案是答案未显示阶段的 primary action：

- 文案：`显示答案`。
- 快捷键提示：`Space`，作为辅助信息，不抢主按钮视觉焦点。
- 使用 `--color-brand`、`--color-brand-strong` 和 `--color-brand-contrast`。
- 最小点击区域约 `44×44px`，不因紧凑窗口缩小到难以点击。
- 答案显示后 disabled，但不消失、不移动、不改变布局。

### 5.2 不认识按钮

- 文案：`不认识`，快捷键提示 `←`。
- 答案未显示时 disabled；答案显示后启用。
- 使用 `--learning-unknown-background`、`--learning-unknown-color` 或现有 danger Token。
- 语义必须由文字、焦点和状态共同传达，不能只依赖红色。

### 5.3 认识按钮

- 文案：`认识`，快捷键提示 `→`。
- 答案未显示时 disabled；答案显示后启用。
- 使用 `--learning-known-background`、`--learning-known-color` 或现有 success Token。
- 与“不认识”保持相近宽度、相同高度和同等可见性。

### 5.4 交互状态矩阵

| 状态 | 显示答案 | 认识 / 不认识 | 规则 |
|---|---|---|---|
| Default | 品牌主按钮 | 答案未显示时 disabled | 位置稳定，文字清晰 |
| Hover | 背景或边框轻微增强 | 启用后轻微表面变化 | 120–180ms，不能位移布局 |
| Active | 轻微缩放或按下反馈 | 同样处理 | 立即反馈，不延迟提交 |
| Disabled | 统一弱化，约 `0.45` 透明度 | 答案未显示时统一弱化 | 不隐藏、不改变尺寸、不承担新语义 |
| Focus | 可见 focus ring | 可见 focus ring | 不移除浏览器/自定义焦点可视性 |

### 5.5 键盘与语义

- 使用原生 `button` 表达按钮，不使用带 `onClick` 的 `div`。
- Tab 顺序与视觉顺序一致。
- `focus-visible` 必须在深色和浅色主题下清晰可见。
- Icon/快捷键辅助信息不能取代按钮文字。
- 不新增键盘快捷键，不改变现有快捷键的含义。

## 6. 学习反馈设计

### 6.1 答案出现动画

答案显示时只对答案区域使用低幅度淡入或轻微上移：

- 建议时长：`160–220ms`。
- 推荐属性：`opacity`、`transform`。
- 不动画卡片高度、padding、按钮位置或页面整体布局。
- 动画不能阻塞用户继续判断，也不能影响 `onAnswer` 的保存时机。

### 6.2 判断反馈

用户点击判断按钮或使用 Left/Right Arrow 后：

- 按钮立即显示 active 状态。
- 使用 success/danger 语义进行短暂确认，但保留“认识/不认识”文字。
- 不新增 toast、弹窗、分数、连击、音效或游戏奖励。
- 反馈只确认本次判断已被接受，不改变业务结果。

### 6.3 下一词过渡

- 旧答案不能残留。
- 新单词应立即成为唯一主焦点。
- 计数器与实际索引保持同步。
- 建议使用 `160–240ms` 的淡出/淡入或轻微位移。
- 不使用大幅滑屏、旋转、翻牌或连续循环动画。
- 不能让用户等待动画结束后才可继续操作。

### 6.4 Reduced Motion

在 `prefers-reduced-motion: reduce` 下：

- 取消位移、模糊、连续循环和非必要淡入。
- 保留静态的答案出现、按钮启用和判断语义变化。
- 不改变交互顺序、快捷键语义、保存时机或页面可用性。

## 7. 响应式设计

### 7.1 `920×620` 紧凑窗口

- Header 允许自然换行，标题、模式和进度仍然可见。
- Word Card 使用较小但稳定的上下内边距，避免固定高度制造无效留白。
- 单词正文、中文释义和答案允许多行。
- Action 维持两列等宽；若内容空间不足，按钮可以在纵向空间中完整展开，但不压缩文字。
- 页面允许纵向滚动，禁止横向滚动。
- Feedback 保持低强调，不与判断按钮抢占空间。

### 7.2 `1180×760` 标准窗口

- Header 默认保持一行。
- Word Stage 居中并拥有充足上下呼吸空间。
- Word Card 是页面主区域，正文阅读宽度约 `760px` 内。
- Action 紧跟 Word Card，两个判断按钮等宽排列。
- 多余空间优先增加留白，不新增统计、计时或奖励模块。

### 7.3 全屏与宽屏

- 页面内容容器最大宽度约 `1080–1120px`，避免无限拉伸。
- Word Card 可适度扩大宽度，但不让字号按窗口无限放大。
- 单词与操作区域保持视觉关联，不能被宽屏空白过度分散。
- 纵向空间增加时优先增加 Word Stage 呼吸感。

### 7.4 字体缩放

支持现有 `--font-scale` 的 100%、125%、150%、175% 档位：

- 单词和释义优先保证完整可读。
- 按钮最小点击区域不因字号缩放而失效。
- Header 中的模式按钮和进度可换行，但不得重叠。
- 答案区可自然增高，不能裁剪长文本。
- 不通过修改词库文本、学习记录或数据库设置字段实现字体适配。

## 8. 深色 / 浅色主题适配

学习页继续使用现有 Theme Token、Typography Token 和 Layout Token，不创建新的视觉体系。

### 8.1 Theme Token

| 用途 | 继承 Token | 学习页使用 |
|---|---|---|
| 页面背景 | `--color-bg` | Study Page 根背景 |
| Word Card | `--color-surface-elevated` | 当前单词主容器 |
| 控件表面 | `--color-control`、`--color-control-hover` | 模式和次级控制 |
| 主文字 | `--color-text` | 单词、答案和主要标题 |
| 辅助文字 | `--color-text-muted`、`--color-text-subtle` | 进度、编号、提示和说明 |
| 主行动 | `--color-brand`、`--color-brand-strong` | 显示答案 |
| 成功语义 | `--color-success`、`--color-success-surface` | 答案、认识、完成 |
| 错误语义 | `--color-danger`、`--color-danger-soft` | 不认识反馈 |
| 焦点 | `--color-focus`、`--shadow-focus` | focus-visible |
| 边框 | `--color-border`、`--color-border-strong` | 卡片、控件和分隔 |

### 8.2 深色主题

- 保持深灰/午夜蓝背景和低对比边界。
- 单词正文使用高可读但非纯白的主文字色。
- 品牌蓝只用于主行动、active 和焦点关联，不大面积铺满卡片。
- 成功绿和错误色保持语义分工，不将整个答案卡染成状态色。

### 8.3 浅色主题

- 使用现有 `data-theme="light"` 映射。
- 背景、卡片、边框、主文字和辅助文字分别验证对比度。
- 浅色背景上的正文和按钮文字至少达到 4.5:1 的正常文本对比度目标。
- 主题切换不改变内容顺序、按钮位置、操作语义或快捷键。

### 8.4 无障碍基线

- 不用颜色作为唯一状态表达方式。
- 正常文本目标对比度至少 `4.5:1`，大字号文字至少 `3:1`。
- 所有按钮具备可读名称和清晰 focus-visible。
- 不使用 emoji 或 Unicode 字符作为布局依赖的稳定图标。
- 禁止通过 `overflow: hidden` 隐藏关键学习内容。

---

## 9. 与 Design System 对应关系

### 9.1 Token-first

本方案不直接定义新的颜色、字体和间距值，而是把学习页的语义映射到现有全局 Token：

```text
Primitive / Global Token
        ↓
Semantic Token
        ↓
Learning Page Token
        ↓
Header / Word Card / Action / Feedback
```

学习页可使用以下语义别名，但实际值必须来自全局体系：

- `--learning-card-background` → `--color-surface-elevated`
- `--learning-word-color` → `--color-text`
- `--learning-answer-color` → `--color-success`
- `--learning-primary-background` → `--color-brand`
- `--learning-known-color` → `--color-success`
- `--learning-unknown-color` → `--color-danger`
- `--learning-focus-ring` → `--shadow-focus`
- `--learning-disabled-opacity` → 现有 disabled 规则

### 9.2 Component State Matrix

学习页的状态应按组件和阶段统一表达：

| 组件 | 提示阶段 | 答案阶段 | 切换阶段 |
|---|---|---|---|
| Word Card | 显示正面提示 | 显示答案 | 清除旧答案并显示新提示 |
| 显示答案 | enabled primary | disabled | 恢复 enabled |
| 不认识 | visible disabled | visible enabled | 恢复 disabled |
| 认识 | visible disabled | visible enabled | 恢复 disabled |
| Feedback | 准备好后查看答案 | 请选择你的判断 | 低幅度过渡 |
| Progress | 当前索引 | 当前索引 | 与下一词索引同步 |

组件状态的变化只能改变视觉表现和可访问性表达，不能新增业务状态、改变学习阶段或修改数据流。

### 9.3 UI-UX Pro Max 规则落地

- Accessibility：键盘可用、focus-visible、对比度和非颜色语义。
- Interaction：按钮状态完整、点击区域稳定、hover 不承担唯一可用入口。
- Performance：答案区预留空间，避免内容跳动和布局重排。
- Responsive：容器使用最大宽度和可换行策略，禁止横向溢出。
- Typography：正文保持舒适行高，长文本按可读性换行。
- Animation：只动画 `opacity` 和 `transform`，使用短时长并尊重 reduced motion。
- React：继续使用语义化 HTML；本阶段不抽取新的业务 hook 或重构业务状态。

## 10. 实现边界

### 10.1 允许调整

- 学习页布局包装、展示层 class 和可访问性属性。
- Word Card、Action、Feedback 的 CSS 布局、间距、颜色、字体、圆角、边框和阴影。
- 深色/浅色主题下的学习页表现层映射。
- 答案出现、判断反馈和下一词切换的轻量视觉过渡。
- `920×620`、`1180×760`、宽屏和全屏下的表现层适配。

### 10.2 明确禁止调整

- 增加新功能、复习功能、统计功能、音频功能或新的学习步骤。
- 修改学习算法、学习队列、掌握等级、错词逻辑或学习顺序。
- 修改 SQLite 表结构、字段、保存时机、记录模型或数据服务。
- 修改 IPC、Electron 主进程、preload、文件访问或数据通信。
- 修改词库 JSON、词库格式、词库内容或词库导入逻辑。
- 修改 `getFrontText`、`getAnswerText`、`handleStudyKeyDown` 的业务语义。
- 修改 `onAnswer`、`onIndexChange`、`onModeChange` 的调用时机和数据含义。
- 修改 Space、Left Arrow、Right Arrow、Esc 的快捷键语义。
- 为音标或例句新增字段、数据流、业务组件或虚假内容。

### 10.3 实现前检查

实现前必须确认：

1. `StudyPage` props、回调和现有状态判断保持原样。
2. 答案显示前后的 disabled 状态与状态矩阵一致。
3. 现有学习记录、进度恢复、完成状态和再学一轮流程不受影响。
4. 学习页样式变更不会污染其他页面的 Token 或组件。
5. 所有可视变化可以通过现有测试、构建和手动窗口验收验证。

### 10.4 设计验收标准

- 用户进入学习页后能立即识别当前单词、模式、进度和下一步操作。
- Word Card 在英译中、中译英、长释义和高字号下均可读、不裁剪、不溢出。
- 显示答案、认识、不认识的状态清晰，且不改变操作布局。
- 鼠标、键盘和 focus-visible 状态表达一致。
- 答案出现和下一词切换不产生明显布局跳动或操作阻塞。
- `920×620`、`1180×760`、宽屏和全屏无横向溢出、遮挡或白边。
- 深色和浅色主题使用同一套 Token 语义，文字对比度符合可读性要求。
- 100%、125%、150%、175% 字体缩放下按钮、释义和进度不重叠。
- reduced-motion 环境下仍能完整学习和完成判断。
- 学习算法、SQLite、IPC、词库和数据流程没有任何变化。

---

## 方案结论

学习页采用“节奏卡片”方案：Word Card 保持页面唯一主焦点，显示答案按钮位于卡片内，认识/不认识按钮固定在卡片下方。通过稳定答案区、明确阶段状态、统一 Token 和低幅度反馈，降低重复学习的认知负担，同时不改变 LexiStudy 现有学习逻辑和数据边界。
