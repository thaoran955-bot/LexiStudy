# LexiStudy v0.2.0 UI/UX 开发路线

## 1. v0.2.0 开发目标

v0.2.0 是 LexiStudy 的纯 UI/UX 优化版本，不增加新的业务功能。主要目标是：

- 让应用适配 `920×620` 最小窗口、标准窗口和全屏窗口。
- 取消顶部 Electron 菜单作为常规导航入口，统一由左侧导航承载页面切换。
- 解决固定侧栏、固定内容宽度和固定间距造成的比例失衡。
- 让首页、学习、统计、设置和词库管理页面在窄窗口下可读、可滚动、可操作。
- 建立统一的颜色、间距、圆角、字体缩放、图标和动效 token。
- 提升键盘焦点、鼠标反馈、状态提示和 Windows 桌面窗口体验。
- 消除启动、最大化和全屏状态下的白边、白闪和窗口内容断层，并为未来 Stats Dashboard 预留展示空间。
- 保持 v0.1.1 的 SQLite 数据、学习算法、词库和 IPC 行为完全兼容。

## 2. 当前确定优化项目

### 2.1 应用外壳和窗口适配

- 将固定的页面外边距和最大宽度调整为响应式 token。
- 让内容区域具备 `min-width: 0` 和稳定的纵向滚动策略。
- 优化侧栏在紧凑桌面和全屏状态下的宽度、间距和底部进度区。
- 检查 Electron 初始窗口、最小窗口、最大化和全屏状态下的内容比例。
- 统一 Electron 窗口背景、页面背景、加载状态和错误状态，消除白边与白闪。
- 移除顶部菜单的用户可见页面导航，保留左侧导航作为唯一主导航；不改变路由和业务 IPC。

### 2.2 设计系统整理

- 将全局 CSS 中重复的颜色、间距、圆角、边框和字号整理为 CSS 变量。
- 统一卡片、面板、按钮、标签、进度条、空状态和错误状态的视觉规则。
- 统一图标占位、对齐、尺寸和颜色语义。
- 建立深色默认 token，并准备浅色 token，不新增业务设置字段。
- 建立 `--font-scale` 四档字体缩放 token（100%、125%、150%、175%），确保字号变化不会破坏按钮、单词卡和统计网格。
- 为现有加载状态加入非阻塞启动动画规范，不新增启动流程或业务等待。

### 2.3 首页 HomePage

- 保持当前词库、今日目标、进度和继续学习入口的业务内容不变。
- 优化首屏层级，让当前词库和主学习 CTA 在不同窗口高度下仍然优先可见。
- 将进度卡和指标卡改为可伸缩网格，减少宽窗口空白。
- 让今日目标按钮在紧凑窗口下自然换行，避免压缩标题和按钮。

### 2.4 学习 StudyPage

- 保持一次显示一个单词、答案显示、认识/不认识和当前学习模式不变。
- 让单词卡在宽窗口下适度扩展，在矮窗口下减少无效上下留白。
- 使英译中和中译英的长文本保持可读，避免超出卡片。
- 优化模式按钮、计数器、显示答案按钮和答题按钮的布局换行。
- 保持 Space、Left Arrow、Right Arrow、Esc 的现有语义和监听逻辑，不改快捷键实现。

### 2.5 统计 StatsPage

- 将四项指标做成可降级的响应式网格：宽屏四列、标准窗口两列、紧凑窗口一列或两列。
- 掌握等级分布和错误 Top 20 在宽屏并列，在紧凑窗口纵向排列。
- 保持错误列表的滚动边界和文字省略，避免长释义撑破面板。
- 预留 Stats Dashboard 的网格容器和面板插槽，但 v0.2.0 不新增指标、图表、筛选器或统计计算。
- 只改善数据显示比例，不添加新的指标、筛选器或统计算法。

### 2.6 设置 SettingsPage

- 将设置行在宽窗口横向排列，在紧凑窗口纵向排列。
- 让每日目标、学习模式和快捷键说明在窄窗口保持足够点击区域。
- 统一保存中、保存成功和保存失败的反馈位置和颜色。
- 保持现有 SQLite 设置保存调用，不增加新的设置类型。

### 2.7 词库管理 DictionaryManagementPage

- 将导入表单从宽屏三列布局平滑降为窄屏单列布局。
- 优化词库名称、词数、来源标签和当前使用状态的层级。
- 长词库名称和错误提示需要可换行或省略，不遮挡切换按钮。
- 保持 JSON 导入、取消、切换词库和词库隔离行为不变。

## 3. 建议开发阶段

### 阶段一：UI 基线和 token

- 记录 v0.1.1 五个页面在最小、标准、全屏尺寸下的现状。
- 在全局样式中定义颜色、字号、间距、圆角、阴影、断点和动效 token。
- 先验证 token 不改变现有页面内容和业务状态。

### 阶段二：AppShell 和响应式容器

- 调整侧栏、内容区域、页面容器和滚动边界。
- 完成宽屏、标准窗口和紧凑窗口的布局验收。
- 只修改展示结构和 CSS，不触碰路由、服务和 IPC。

### 阶段三：逐页 UI 重构

按以下顺序执行：

1. StudyPage：优先保证核心学习体验。
2. HomePage：统一首页层级和目标入口。
3. StatsPage：处理密集数据的响应式网格。
4. SettingsPage：处理设置行和操作反馈。
5. DictionaryManagementPage：处理导入表单和词库列表。

每完成一个页面，分别在 `920×620`、`1180×760` 和全屏尺寸验证，再进入下一个页面。

### 阶段四：主题、字体、图标和动效

- 应用深色 token 并校验现有视觉基线。
- 补充浅色 token 设计稿或样式预留，但不强制增加主题切换业务。
- 统一字体层级、四档字体缩放、图标对齐、focus-visible、hover、disabled 和 reduced-motion 行为。
- 在现有 loading-screen 上实现非阻塞的短启动动画，并验证无白闪、无白边。

### 阶段五：稳定性和回归验收

- 验证页面切换、学习答题、快捷键、词库导入/切换、统计加载和设置保存。
- 关闭并重启应用，确认 SQLite 学习数据和设置保持不变。
- 在发布版和开发版分别验证，不修改 `vocabulary_final.json`。
- 记录截图和窗口尺寸，确认无黑屏、白屏、横向溢出、按钮遮挡和滚动异常。
- 确认顶部菜单不再重复提供页面导航，左侧导航可完成全部现有页面跳转。

## 4. 后续版本功能规划

以下内容不属于 v0.2.0，只作为后续产品规划，不在本版本预先实现：

### v0.2.x：UI 细节和可访问性

- 更完整的主题切换体验和主题偏好保存。
- 更细致的可访问性审计、字号偏好和高对比度方案。
- 学习卡、进度反馈和错误提示的微交互优化。

### v0.3.x：Stats Dashboard、复习和学习体验

- 在 v0.2.0 预留的网格和面板插槽中加入更完整的 Stats Dashboard。
- 增加复习日历、趋势展示、复习计划视图和更细粒度的学习队列控制。
- 这些内容需要单独评审统计数据和学习数据模型，不能提前写入 v0.2.0。

### v0.4.x：本地数据管理

- 本地学习数据查看、备份、恢复和导出。
- 词库元信息维护、排序和筛选。
- 需要单独设计数据安全、文件格式和错误恢复流程。

## 5. 明确不属于 v0.2.0 的内容

- 新增学习功能、学习模式或新的业务组件。
- 修改掌握等级、错词复习、学习队列和统计计算。
- 修改 SQLite 表、字段、迁移和数据库路径。
- 修改 `resources/vocabulary_final.json`、词库格式、导入解析和词库隔离逻辑。
- 修改 preload、IPC channel、Electron 菜单通信和数据服务接口。
- 增加账号、登录、联网、云同步、远程服务或用户系统。
- 增加复杂统计指标、导出功能、通知和自动提醒。
- 通过 UI 重构顺便改变快捷键语义或页面导航行为。
- 在 v0.2.0 实现 Stats Dashboard 的新指标、图表、筛选器或统计计算；本版本只预留空间。
- Windows 安装包发布流程和版本号升级；除非 UI 资源需要单独验证，否则不属于本版本范围。

## 6. v0.2.0 完成标准

- 五个页面在目标窗口尺寸下无横向溢出，布局比例稳定。
- 全屏状态合理利用空间，内容不会过度拉伸或集中在左上角。
- 顶部菜单不再作为常规页面导航，左侧导航可完成全部现有页面跳转。
- 所有现有按钮、路由、快捷键和状态反馈行为保持一致。
- UI 改造前后 SQLite 数据库结构、学习记录、词库文件和 IPC 调用结果一致。
- 字体缩放四档、启动动画、主题 token、图标和窗口边缘视觉通过验收。
- Stats Dashboard 仅有预留空间，不产生新的业务数据。
- `npm.cmd run test -- --run`、`npm.cmd run build` 和发布版启动回归通过。
- 完成开发版、安装版和重启恢复验证后，才能将 v0.2.0 UI 版本标记为稳定候选。
