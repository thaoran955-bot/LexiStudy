# LexiStudy v0.2.0 UI 设计规范

## 1. 版本定位

LexiStudy v0.2.0 是纯 UI/UX 优化版本，目标是让 v0.1.1 Stable 的现有功能在不同桌面窗口尺寸下更稳定、更清晰、更易用。

本版本只调整表现层：布局、间距、视觉层级、主题 token、字体、图标、动效、焦点状态和窗口适配。不增加业务功能，不改变学习流程和数据含义。

当前 UI 基线：

- React 使用 `AppShell` 承载侧栏和 `Outlet` 页面区域。
- 主导航包含首页、学习、统计、设置和词库入口，路由继续使用现有 HashRouter。
- v0.1.1 当前同时存在 Electron 顶部菜单和页面左侧导航；v0.2.0 的目标是取消顶部菜单作为常规用户入口，统一使用左侧导航。
- 全局样式集中在 `src/styles/global.css`。
- Electron 初始窗口为 `1180×760`，当前最小窗口为 `920×620`。
- 页面使用固定侧栏、固定最大内容宽度和大量固定像素间距。
- 当前默认是深色界面，词库和学习数据仍然是本地只读/本地持久化架构。

## 2. UI 设计原则

### 2.1 学习优先

- 学习页面的单词卡和答题操作始终是最高视觉层级。
- 首页的今日目标、当前词库和继续学习入口必须在首屏可见。
- 统计与设置优先保证可读性，不用装饰性元素抢占注意力。

### 2.2 稳定比例

- 使用容器、网格和 `clamp()` 控制尺寸，不让窗口变大后内容只停留在左上角。
- 使用 `minmax(0, 1fr)`、`min-width: 0` 和可换行布局处理长文本。
- 不以缩小字体作为唯一的窄窗口适配方案。

### 2.3 清晰层级

- 每个页面只保留一个主标题和一个主操作。
- 卡片、面板、辅助说明和状态反馈使用稳定的层级关系。
- 颜色语义统一：主色表示行动和进度，绿色表示认识/完成，暖色表示错误或提醒。

### 2.4 桌面应用感

- 支持鼠标、键盘、窗口缩放和全屏状态。
- 可点击元素必须有 hover、focus-visible、disabled 状态。
- 不依赖浏览器默认滚动、焦点或按钮样式来表达关键状态。

### 2.5 保持克制

- 不引入复杂渐变、持续动画或与学习无关的装饰。
- 不新增业务组件，不改变现有页面的业务入口和操作顺序。
- 每一项视觉变化都应能说明它改善了可读性、操作效率或窗口适配。
- 统一导航入口，避免顶部菜单和左侧导航重复表达同一组页面跳转。

## 3. 布局规范

### 3.1 应用外壳

- `.app-shell` 使用 `min-height: 100vh`，主内容区域使用 `min-width: 0`，避免 flex 子项导致横向溢出。
- 侧栏保持桌面导航语义，宽度使用 token 控制，标准宽度约 `240px`，紧凑窗口可收窄到约 `208px`。
- 内容区域占据剩余宽度，页面容器使用 `width: min(100%, var(--page-max-width))` 居中。
- 内容区域设置独立的纵向滚动策略，滚动时侧栏和页面标题的行为保持稳定。
- 全屏时不拉伸文字和按钮，而是让页面容器、统计网格和学习卡在允许范围内扩展。

### 3.2 页面容器

- 标准页面最大宽度建议为 `1120–1200px`，根据页面密度选择具体值。
- 页面左右内边距使用 `clamp(24px, 5vw, 72px)`，避免固定 `72px` 在窄窗口中挤压内容。
- 页面顶部间距使用 `clamp(28px, 5vh, 56px)`，兼顾矮窗口和全屏高度。
- 页面标题、说明文字和主操作在宽窗口横向排列，在紧凑窗口纵向排列。

### 3.3 网格和面板

- 首页指标使用 `repeat(3, minmax(0, 1fr))`，统计指标使用 `repeat(4, minmax(0, 1fr))`，在断点处降为两列或一列。
- 统计页面的掌握分布和错误排行在标准宽度下并列，紧凑窗口下纵向排列。
- 导入表单在宽窗口为三列，窄窗口改为单列，按钮占满可用宽度。
- 所有面板允许内容收缩，长词库名称、释义和状态提示使用省略或换行规则，不突破页面宽度。

### 3.4 尺寸支持范围

- 紧凑桌面：`920×620`，保证无横向滚动、按钮可见、学习卡和答题区完整。
- 标准窗口：约 `1180×760`，作为主要视觉验收尺寸。
- 宽窗口/全屏：`1440px` 及以上宽度，扩展内容容器和网格空白，不放大到失真。
- 低于当前 Electron 最小窗口的尺寸不作为 v0.2.0 首要目标；如果后续调整最小窗口，必须单独完成键盘、导入和学习操作验收。

### 3.5 窗口边缘与视觉统一

- `html`、`body`、React 根节点、加载状态和错误状态使用同一背景 token，启动、最大化和全屏时不出现白边或白色闪屏。
- Electron `BrowserWindow` 的背景色与页面背景保持一致，窗口内容边缘不使用与主题冲突的默认白色。
- 卡片边框、页面背景和系统窗口边缘需要形成稳定层级；不能通过增加厚重外框制造白色描边。
- 保留 Windows 原生窗口框架，不在 v0.2.0 引入自定义标题栏；窗口视觉统一只处理内容区背景、边缘、滚动条和状态过渡。
- 窗口缩放、最大化和全屏恢复后，背景、侧栏和内容区必须无断层、无闪烁、无空白条。

## 4. 响应式设计规范

### 4.1 断点策略

使用基于内容的桌面断点，而不是针对单一设备型号：

- `≥ 1280px`：宽桌面，侧栏保持完整，内容容器可扩展，统计网格保持高信息密度。
- `1050–1279px`：标准桌面，页面左右内边距收窄，统计和管理面板保持两列。
- `920–1049px`：紧凑桌面，侧栏收窄，页面头部和表单允许换行，统计列改为单列。
- 每个断点都必须验证英文长词、中文长释义、按钮焦点和滚动行为。

### 4.2 全屏行为

- 全屏时主内容继续居中，但最大宽度扩大到设计上限；不出现大面积无意义空白。
- 首页进度卡可增加左右留白，学习单词卡可增加可读的卡片宽度，但不无限放大字号。
- 统计网格使用额外空间，不改变指标定义和数据排序。
- 侧栏不随高度拉伸内容，只让进度卡和导航底部保持稳定位置。

### 4.3 窄窗口行为

- 页面标题与主按钮纵向排列。
- 目标按钮、模式按钮和词库操作按钮允许换行或占满一行。
- 所有固定宽度元素改为 `min-width` 或内容自适应，禁止硬编码造成溢出。
- 纵向内容可以滚动，滚动不应触发按钮默认行为或破坏快捷键。

## 5. 导航系统规范

- 保留现有主导航项目和路由：词库、首页、学习、统计、设置。
- v0.2.0 取消顶部 Electron 菜单作为常规用户导航，统一由左侧导航承载页面入口；不再让用户在两个位置选择相同页面。
- 保留 `AppShell`、`Outlet` 和 HashRouter 路由架构，不改变路由目标、页面业务入口和数据服务接口。
- 若取消顶部菜单需要调整菜单呈现 wiring，只允许移除/隐藏导航菜单入口，不改学习、数据库、词库或文件导入 IPC 数据通信。
- 当前页面使用清晰的 active 状态，颜色、背景和左侧/图标提示保持一致。
- 侧栏在紧凑窗口只做视觉收窄或图标化处理，不改变导航目标；若需要折叠交互，应作为纯展示层状态，不新增业务状态。
- 页面内部返回、继续学习、选择词库等入口保持现有行为和路径。
- 导航元素必须支持键盘 focus-visible，并保证焦点环与深浅主题都有足够对比度。

## 6. 深色/浅色主题规范

### 6.1 主题 token

将当前散落在全局 CSS 中的颜色整理为表现层 CSS 变量，包括：

- `--color-bg`：应用背景。
- `--color-surface`：卡片和面板背景。
- `--color-surface-elevated`：弹出或重点面板背景。
- `--color-border`：边框和分隔线。
- `--color-text`、`--color-text-muted`、`--color-text-subtle`：文字层级。
- `--color-brand`、`--color-brand-strong`：主按钮、链接、active 状态和品牌光。
- `--color-focus`：键盘焦点环和可访问性提示。
- `--color-success`、`--color-warning`、`--color-danger`：状态语义。

### 6.2 深色主题

- 深色主题是 v0.2.0 的默认视觉基线，延续深灰/午夜蓝背景和浅色文字；品牌蓝承担主行动，黄绿色只承担认识、完成和进度提升语义。
- 面板之间必须有足够的亮度层级，不能只依赖边框区分。
- 主色用于有限的行动和进度反馈，不大面积铺满背景。

### 6.3 浅色主题

- 浅色主题只定义对应 token，不改变业务数据、设置模型或 IPC。
- 浅色背景下的文字、边框、状态色必须重新验证对比度，不能直接反转深色值。
- 浅色主题实心品牌按钮使用白色文字配品牌蓝；深色文字只用于浅色 focus 表面或低填充控件。
- 是否在 v0.2.0 暴露主题切换入口，必须作为独立的 UI 决策；本规范不要求新增主题持久化功能。

## 7. 字体系统规范

- 运行时默认字体栈为 `Segoe UI Variable`, `Segoe UI`, `Microsoft YaHei UI`, `Microsoft YaHei`, `system-ui`, `sans-serif`；不联网下载字体。
- `Plus Jakarta Sans` 或 `Geist Sans` 只作为可选品牌字体方向，未随应用本地提供时直接使用默认字体栈。
- 页面标题、卡片标题、正文、辅助说明和数据数字分别建立字号 token，避免当前 `10–68px` 的零散硬编码。
- 建议层级：页面标题 `30–36px`、区块标题 `16–20px`、正文 `13–15px`、辅助文字 `11–12px`、大数字按页面密度使用 `40–64px`。
- 正文行高保持 `1.45–1.7`，中文释义和中译英正面需要允许多行展示。
- 单词卡英文单词保持明显主层级，超长单词或释义必须缩放或换行，而不是遮挡。
- 字体替换不得改变学习数据、词库文本或业务组件接口。

### 7.2 字体缩放系统

- 使用统一的 `--font-scale` 表现层 token，默认值为 `1`，提供 `1`、`1.25`、`1.5`、`1.75` 四档，对应 100%、125%、150%、175%。
- 字体缩放同时影响页面标题、正文、辅助说明、按钮文字、统计数字和学习卡文字；间距和卡片高度只做必要的联动调整。
- 缩放后必须保持按钮最小点击区域、单词卡完整显示、中文释义换行和统计数字不重叠。
- v0.2.0 只建立 CSS token 和页面适配规则，不新增 SQLite 设置字段；用户可见的字体偏好入口可作为后续 UI 版本内容。
- 字体缩放不得通过修改词库文本、学习记录或业务组件接口实现。

## 8. 图标系统规范

- 保留当前图标语义和入口，不改变导航或按钮行为。
- 将当前散落的 Unicode 图形统一为固定的图标尺寸、颜色和对齐规则。
- 导航图标建议使用 `18–20px`，状态图标建议使用 `16–24px`，不得仅靠字体字符宽度定位。
- 图标必须有可读的文字或 `aria-label`，不能用颜色作为唯一含义。
- 继续使用现有 `assets/icon.ico` 作为 Windows 应用图标；页面图标系统与 Electron 应用图标分离管理。
- 如需抽取展示型图标组件，只允许封装外观和可访问性，不承载导航、学习或数据逻辑。

## 9. 动效规范

- 页面和按钮动效只用于反馈状态变化，不用于持续吸引注意力。
- 交互反馈建议使用 `120–180ms`，面板或页面状态变化建议不超过 `240ms`。
- 保留或重做按钮 hover、focus、disabled、保存反馈和进度条变化；不改变事件触发时机。
- 学习页面切换单词时如果增加过渡，必须保证答案显示、认识/不认识和快捷键不会被动画阻塞或重复提交。
- 支持 `prefers-reduced-motion: reduce`，在减少动效设置下关闭位移和非必要过渡。
- 动效不能替代错误提示、焦点提示或文字状态。

### 9.1 启动动画

- 使用现有 `loading-screen` 作为启动状态的视觉承载，不新增业务启动流程或第二个窗口。
- 启动动画只做短暂的淡入、品牌标记出现或内容占位过渡，建议总时长 `160–240ms`，不得阻塞词库加载、数据库初始化或路由渲染。
- 词库加载失败时直接显示现有错误状态，不用动画掩盖错误，也不延迟错误提示。
- 应用从启动状态进入首页后只执行一次；重新进入页面、切换词库和答题不重复触发启动动画。
- `prefers-reduced-motion: reduce` 下使用静态加载状态，不执行位移和淡入动画。

## 10. 未来功能预留规范

以下只预留视觉位置和扩展边界，不在 v0.2.0 实现业务功能：

- 主题切换、主题偏好和更多外观设置。
- 更详细的复习日历、趋势图和统计筛选。
- 本地数据管理、备份和导出入口。
- 多词库筛选、排序和更丰富的词库元信息。
- Stats Dashboard 的更多卡片、趋势图、筛选区和可视化组件；v0.2.0 只预留容器和网格空间，不新增统计数据或计算逻辑。
- 学习提醒、通知和更多学习模式。

预留区域必须显示为低干扰的占位或说明，不创建虚假的数据，不新增数据库字段，不改变现有接口。

## 11. 技术实施边界

### 允许调整的表现层范围

- `src/styles/global.css`：token、布局、断点、状态和动效样式。
- `src/components/AppShell.tsx`：侧栏、页面容器和导航的展示结构。
- 五个业务页面及快捷键说明页的展示性 class、布局包装和可访问性属性。
- `electron/main.ts` 的窗口尺寸、可调整大小和背景表现配置，前提是不改变加载路径、数据库初始化和业务 IPC 行为。
- `electron/menu.ts` 或相关菜单呈现 wiring：仅用于取消顶部菜单的用户可见导航，不改数据 IPC channel、preload API 和业务服务调用。

### 明确禁止修改

- SQLite 数据库表、字段、迁移和学习记录逻辑。
- 学习算法、掌握等级、错词复习和学习队列。
- `resources/vocabulary_final.json` 及词库格式。
- preload、业务 IPC channel、数据通信和数据服务接口；顶部菜单的纯导航呈现 wiring 不属于业务数据逻辑。
- 页面业务入口、导航目标和快捷键语义。
- 不联网、不登录、不云同步的产品边界。

## 12. UI 验收标准

- 在 `920×620`、`1180×760` 和宽屏/全屏尺寸下无横向溢出。
- 顶部菜单不再作为常规页面入口，左侧导航成为唯一的主页面导航。
- 五个主要页面内容层级一致，主操作可见且可操作。
- 学习页面单词、释义、答题按钮和快捷键状态不被窗口尺寸遮挡。
- 统计指标和词库列表在窄窗口下按规则换列或换行。
- 深色主题对比度和 focus-visible 状态清晰；浅色 token 不出现不可读文字；字体缩放四档不破坏布局。
- 启动、最大化和全屏状态无白边、白闪或内容区断层；启动动画不阻塞应用可用性。
- Stats Dashboard 预留区域存在但不生成新的统计指标或业务数据。
- UI 调整前后，SQLite 数据、词库文件、学习算法、IPC 和快捷键行为保持不变。
