# LexiStudy v0.2.0 视觉系统设计

> 视觉方向：Quiet Scholarly / Luminous Study Desk（安静、专注、可持续进步的学习工作台）

## 0. 版本边界

LexiStudy v0.2.0 是纯 UI/UX Enhancement Only 版本。本文件只定义视觉方向、设计 token 和表现层规则，不定义新的业务功能。

本阶段禁止修改：

- 学习流程、学习算法、掌握等级和错词复习。
- SQLite 数据库结构、学习记录和设置数据模型。
- `resources/vocabulary_final.json` 和词库格式。
- preload、IPC channel、数据服务和文件导入逻辑。
- 现有页面的业务入口、路由语义和快捷键语义。

本文件中的“主题”“字体缩放”“启动动画”和“Stats Dashboard 预留”都只表示表现层设计边界；不代表本阶段新增业务功能或数据字段。

v0.2.0 的用户可见主导航统一为左侧导航；取消顶部 Electron 菜单的页面导航只属于表现层入口整理，不改变路由、数据 IPC 或业务服务。

## 1. 品牌视觉定位

### 1.1 品牌关键词

- **专注 Focused**：减少噪音，让用户快速进入一个单词的记忆状态。
- **可靠 Reliable**：本地、稳定、可恢复，视觉上避免夸张的游戏化奖励。
- **持续 Steady**：进度被清晰看见，但不过度制造压力。
- **清爽 Clear**：像一张整理好的学习桌，而不是信息堆叠的后台系统。
- **有光 Luminous**：用克制的蓝色光感表达发现、记忆和前进。

### 1.2 品牌人格

LexiStudy 应像一位安静、可靠、懂学习节奏的桌面助手：

- 不催促，不用红色警报式视觉刺激用户。
- 不把每个区块都做成卡片，不使用装饰代替信息层级。
- 每次操作都有明确反馈，但反馈短、轻、可预测。
- 视觉重点始终回到“当前要学习的单词”。

### 1.3 现有基线与重构方向

当前 UI 已有深色背景、黄绿色主色、圆角卡片和固定侧栏；Windows 应用图标则使用蓝色书签/词汇卡视觉。v0.2.0 的方向不是推翻现有品牌，而是统一它们：

- 以深色石墨和午夜蓝作为基础背景。
- 以品牌蓝作为主行动色，与 Windows 图标建立联系。
- 保留黄绿色作为“认识、完成、进度提升”的语义色，不再让它承担所有主按钮职责。
- 用更清晰的空间、字重和层级替代大量边框与装饰。

### 1.4 视觉方向选择

采用 **Ethereal Glass-lite + Quiet Editorial** 的混合方向：

- 保留轻微的环境光和层次感，但不把整个页面做成玻璃拟态。
- 主要面板使用稳定、不透明的学习桌面表面，保证文字清晰。
- 只在应用背景、当前进度和重点操作附近使用非常轻的蓝色光晕。
- 不使用大面积图片、纹理、噪点或与学习无关的视觉主题。

## 2. 深色模式视觉规范

深色模式是 v0.2.0 的默认基线，目标是长时间学习舒适，而不是追求纯黑科技感。

### 2.1 背景层级

- 应用背景：午夜石墨，避免纯黑造成刺眼对比。
- 侧栏背景：比应用背景略深或略冷，形成稳定的导航边界。
- 内容区背景：允许非常轻的蓝色径向光晕，光晕必须低对比、不影响文字。
- 卡片表面：使用不透明深色表面，确保滚动和窗口缩放时不出现背景透视闪烁。

### 2.2 表面层级

从低到高依次为：

1. `background`：应用整体背景。
2. `surface`：页面卡片、设置行和统计面板。
3. `surface-elevated`：当前学习卡、重要进度卡和重点状态区。
4. `surface-focus`：被选中、聚焦或暂时强调的交互元素。

每上升一级只增加少量明度、蓝色倾向或内侧高光，不使用厚重阴影制造层级。

### 2.3 深色可读性

- 正文使用高亮度但非纯白的文字色，避免长时间阅读疲劳。
- 辅助文字必须与背景保持稳定对比，不使用过低亮度的灰色隐藏关键信息。
- 主色蓝只用于可点击操作、活动状态和关键进度，不铺满大面积面板。
- 错误状态使用低饱和珊瑚色，避免使用高纯度红色制造紧张感。

## 3. 浅色模式视觉规范

浅色模式是与深色模式成对设计的表现层方案，不要求在本阶段增加主题切换或主题持久化功能。

### 3.1 基础气质

- 使用带轻微蓝灰倾向的纸张白，而不是刺眼的纯白。
- 卡片与页面背景通过明度差、极细分隔线和轻微阴影区分。
- 品牌蓝在浅色背景上适当加深，确保按钮文字和 active 状态清晰。
- 黄绿色完成色需要调整为更深的橄榄绿或深青绿，避免浅色背景上对比不足。

### 3.2 浅色表面

- 页面背景：冷白或浅蓝灰。
- 侧栏：略深的浅蓝灰，可与内容区区分但不形成沉重色块。
- 卡片：接近白色，使用柔和阴影或低对比边框。
- 当前学习卡：可使用非常浅的蓝色内发光或渐变，不使用纯蓝大面积填充。

### 3.3 主题一致性

深色和浅色模式必须共享同一套语义 token：背景、表面、文字、边框、品牌、成功、警告、错误。主题切换不能改变组件尺寸、内容顺序、导航目标或数据表达。

### 4.3 使用规则

- 颜色按语义使用，不按页面随意创建新颜色。
- 主色最多承担主 CTA、active 导航、进度和链接四类任务。
- 错误不等于“不认识”：学习结果可以使用较柔和的错误语义，不能把每次答错渲染成系统故障。
- 渐变只允许用于应用背景和重点学习卡，并且必须以低对比为前提。
- 所有文字、按钮、焦点环和状态色都需要在深色/浅色主题分别验证可读性。
- 正文文字目标对比度至少为 `4.5:1`，大字号文字至少为 `3:1`；按钮边界、active 状态和焦点环目标至少为 `3:1`。
- 浅色主题的实心品牌按钮使用白色文字配 `--color-brand` 或 `--color-brand-strong`；深色文字只用于浅色 focus 表面或低填充控件。

## 5. 字体系统设计

### 5.1 字体组合

推荐优先级：

- 运行时默认字体栈：`Segoe UI Variable`, `Segoe UI`, `Microsoft YaHei UI`, `Microsoft YaHei`, `system-ui`, `sans-serif`。
- `Plus Jakarta Sans` 或 `Geist Sans` 只作为可选的品牌字体方向；如果没有随应用本地提供，不联网下载、不阻塞渲染，直接使用默认字体栈。
- 中文使用 `Microsoft YaHei UI` 或 `Microsoft YaHei`，英文和数字优先使用 `Segoe UI Variable`。
- 不引入与系统环境不匹配的装饰字体，不使用衬线字体承载学习卡正文。

本阶段只定义字体策略，不新增字体依赖、不联网下载字体、不改变词库中的英文和中文文本。

### 5.2 字体层级

| 角色 | 建议字号 | 字重 | 用途 |
| --- | --- | --- | --- |
| Display | `40–56px` | 650–700 | 学习卡单词、首页核心数字 |
| Page title | `28–36px` | 650 | 页面主标题 |
| Section title | `16–20px` | 600 | 面板和区块标题 |
| Body | `13–15px` | 400–500 | 正文、释义和设置说明 |
| Label | `11–12px` | 500–600 | eyebrow、标签、统计辅助文字 |
| Caption | `10–11px` | 400–500 | 键位提示和次要说明 |

### 5.3 字体缩放

使用表现层 `--font-scale` token 规划四档：

- 100%：`1`，标准窗口默认值。
- 125%：`1.25`，用于更舒适的长时间阅读。
- 150%：`1.5`，用于较大显示比例或较远观看距离。
- 175%：`1.75`，用于最大可读性优先的场景。

字体缩放必须联动检查行高、按钮点击区、单词卡最大宽度、中文释义换行和统计数字对齐。v0.2.0 不新增 SQLite 字段或设置数据。

### 5.4 排版气质

- 标题使用紧凑字距和明确重量，正文保持开放行高。
- 单词卡英文可使用更大的字号，但不使用过度压缩的字距。
- 中文释义优先保证自然换行，不为了保持单行而缩到不可读。
- 数字使用稳定的数字宽度和对齐方式，方便比较今日进度和统计数据。

## 6. 图标系统设计原则

### 6.1 统一方向

- 使用轻量、几何、单线或简化实心图标，表现“工具”和“学习桌面”而不是游戏徽章。
- 导航图标、状态图标和动作图标分别建立尺寸与语义，不混用 Unicode 字符造成视觉跳动。
- 页面图标与 Windows 应用 `assets/icon.ico` 共享蓝色品牌方向，但不强行复刻应用图标细节。

### 6.2 图标尺寸

- 导航图标：`18–20px`，与文字中心线对齐。
- 按钮尾部图标：`14–16px`。
- 状态/空状态图标：`20–28px`。
- 学习卡重点图标：最多 `32px`，避免抢过单词视觉焦点。

### 6.3 可访问性和状态

- 图标不能独立承担重要语义，必须有文字、`aria-label` 或可读状态说明。
- active、hover、focus、disabled 通过颜色和背景共同表达，不只依赖颜色变化。
- 不使用 emoji 作为稳定 UI 图标，不让不同 Windows 字体渲染造成尺寸差异。
- 图标动画只允许发生在明确的状态变化中，不能持续旋转或闪烁。
- 图标绘制基准为 `24×24` 网格，默认线宽 `1.5–1.75px`，使用 round linecap/linejoin；实现可采用本地 SVG 或已存在的本地图标资源，不新增网络依赖。

## 7. 动效语言设计原则

### 7.1 动效人格

LexiStudy 的动效是“quiet kinetic”：轻、短、可预测，像纸张和卡片在桌面上自然移动，不像游戏奖励或营销页面。

### 7.2 时间与曲线

- 微交互：`120–180ms`，用于 hover、focus、按钮按下和标签颜色变化。
- 页面状态：`180–240ms`，用于面板出现、保存反馈和进度更新。
- 启动过渡：`160–240ms`，只处理现有 loading 状态的视觉进入。
- 使用 `cubic-bezier(0.32, 0.72, 0, 1)` 等带有自然减速的自定义曲线，不使用生硬的线性运动。
- 只动画 `transform` 和 `opacity`，避免动画触发大范围布局重排。

### 7.3 场景规则

- 点击按钮：轻微缩放或颜色过渡，必须立即可再次识别状态。
- 页面切换：使用短暂淡入或轻微位移，不使用大幅滑屏遮挡学习内容。
- 学习答题：答案显示和结果切换不能被动画阻塞，也不能产生重复提交。
- 进度更新：允许进度条柔和过渡，但数值和结果必须立即准确。
- 启动动画只使用现有 `loading-screen`，不创建新的启动窗口或等待流程。

### 7.4 减少动效

支持 `prefers-reduced-motion: reduce`：关闭位移、模糊、连续循环和非必要淡入，只保留清晰的静态状态变化。

## 8. 布局空间设计原则

### 8.1 空间基线

使用 4px 基础单位，主要间距落在 `8 / 12 / 16 / 24 / 32 / 48 / 64px`，避免每个组件独立发明间距。

建议空间 token：

- `space-1 = 4px`
- `space-2 = 8px`
- `space-3 = 12px`
- `space-4 = 16px`
- `space-6 = 24px`
- `space-8 = 32px`
- `space-12 = 48px`
- `space-16 = 64px`

核心布局 token：

- `--sidebar-width = 240px`，紧凑窗口下不低于 `208px`。
- `--page-max-width = 1120px`，宽屏可在 `1200px` 内扩展。
- `--radius-control = 10px`，`--radius-panel = 16px`，`--radius-card = 20px`。
- `--content-gutter = clamp(24px, 5vw, 72px)`。

### 8.2 应用外壳

- 侧栏标准宽度约 `232–248px`，紧凑窗口可以收窄，但不能压缩文字到不可读。
- 内容区使用 `min-width: 0`，页面容器宽度使用 `min(100%, 1120–1200px)`。
- 内容左右留白使用 `clamp(24px, 5vw, 72px)`，全屏时适度增加内容宽度而不是放大字号。
- 页面高度使用 `min-height: 100vh`，内容滚动不让侧栏和背景出现白边或断层。

### 8.3 信息密度

- 首页采用“主进度 + 当前词库 + 今日目标 + 少量指标”的层级，避免统计面板堆叠。
- 学习页面为单一主焦点：单词卡占据视觉中心，模式、计数和答题按钮围绕它组织。
- 统计页面允许更高信息密度，但每个面板内部必须保留稳定的标题、数值和说明间距。
- 设置和词库管理优先保证表单标签、输入区、状态反馈和操作按钮之间的可扫描关系。

### 8.4 全屏和未来预留

- 全屏时内容网格可以扩展，学习卡和统计面板保持合理最大宽度，不出现过度拉伸。
- 为未来 Stats Dashboard 预留一层网格容器和面板插槽；v0.2.0 不新增指标、图表或统计计算。
- 预留区域不使用虚假数据，不放置不可点击的伪按钮，不改变当前页面的信息优先级。

### 8.5 白边与窗口边缘

- `html`、`body`、根节点、加载态和错误态使用同一背景 token。
- Electron `BrowserWindow` 背景色与页面背景保持一致，最大化、全屏和启动时不出现白色闪屏。
- 保留 Windows 原生窗口框架，不在视觉系统阶段引入自定义标题栏。
- 边框采用低对比 hairline 或柔和表面层，不用白色粗边框勾勒每一张卡片。

## 9. 设计验收清单

- 深色模式保持专注、舒适、层级清晰，品牌蓝与完成绿分工明确。
- 浅色模式具备完整语义 token，不出现浅背景上的低对比文字。
- 字体四档缩放不造成按钮、单词卡、释义、统计数字和设置行重叠。
- 图标风格一致，不再依赖 emoji 或 Unicode 字宽表达导航布局。
- 动效短、轻、可中断，减少动效设置下仍然可用。
- `920×620`、`1180×760`、宽屏和全屏状态无横向溢出、白边、白闪或内容断层。
- 左侧导航、现有页面、快捷键和业务状态的语义不改变。
- SQLite、学习算法、词库 JSON、IPC 和数据服务未被视觉实现侵入。
