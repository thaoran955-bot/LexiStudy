# LexiStudy v0.2.0 Word Card 视觉规格

> 版本：`v0.2.0-alpha`
> 适用分支：`feature/v0.2.0-learning-page`
> 文档类型：表现层视觉规格
> 范围：`UI/UX Enhancement Only`

## 1. 文档定位

Word Card 是学习页每一轮学习的唯一主要视觉焦点。本规格定义卡片的视觉层级、尺寸、状态、响应式行为、主题适配和动效边界，供 UI 实现与人工验收使用。

本规格不改变：

- 学习算法、掌握等级、错词复习和学习队列。
- SQLite 表结构、学习记录、保存时机和数据模型。
- `StudyPage` 的 props、回调、快捷键和路由语义。
- 词库 JSON、IPC、preload、数据服务和文件导入逻辑。
- v0.2.0 之外的音频、收藏、笔记、评分、AI 或统计功能。

## 2. 核心视觉方向

Word Card 采用“节奏卡片”方案：

```text
当前提示 → 独立回忆 → 显示答案 → 认识 / 不认识 → 下一词
```

卡片应表现为稳定、低干扰的学习工作表面，而不是游戏奖励面板或词典详情页。

视觉优先级固定为：

1. 当前单词或当前中文提示。
2. 当前阶段可执行的主要操作。
3. 答案内容与认识程度判断。
4. 模式、进度和编号。
5. 快捷键、保存说明等辅助信息。

每个状态只保留一个主视觉焦点。卡片不得使用装饰性插画、徽章、持续发光、强渐变或大幅翻牌动画抢占注意力。

## 3. 内容结构

```text
word-card
├── word-meta              当前词编号 / 可选音标
├── word-prompt            当前单词或中文释义
├── answer-reserve         稳定的答案预留区域
├── answer-content         已显示的答案 / 解释 / 例句
└── answer-reveal-action   显示答案操作
```

判断操作位于卡片下方的 `answer-actions` 区域，不嵌入答案正文中。

### 3.1 当前提示

- 英译中模式：英文单词为主标题。
- 中译英模式：中文释义为当前提示，使用适合中文阅读的行高。
- 单词编号属于辅助 metadata，不得高于单词正文。
- 长单词和长释义必须自然换行，不得裁剪、强制单行或缩小到不可读。
- 现有词条提供音标时才显示音标；没有音标时不显示空占位。

### 3.2 答案区域

- 答案隐藏时保留稳定的最小高度，避免显示答案后按钮大幅位移。
- 答案显示后按“答案 → 解释 → 例句”的顺序排列。
- 解释和例句若已有数据则作为辅助内容；不得为 v0.2.0 生成新数据。
- 不能用 `overflow: hidden`、裁剪或固定高度隐藏长答案。

### 3.3 操作区域

- 答案隐藏时：`显示答案` 是唯一突出操作，提示快捷键 `Space`。
- 答案显示后：`认识` 与 `不认识` 同等重要、同等可见。
- 答案隐藏时，判断按钮可以保持可见但必须 disabled，避免布局重排。
- 不新增翻牌、音频、收藏、评分、跳过或其他业务按钮。

## 4. 尺寸与布局规格

尺寸优先使用项目现有 token；以下值是 Word Card 的语义映射，而不是新建独立视觉体系。

| 项目 | 规格 |
|---|---|
| 内容最大宽度 | `min(100%, 1080px)` |
| Word Card 阅读宽度 | `min(100%, 760px)` |
| 卡片内边距 | `clamp(var(--space-6), 4vw, var(--space-12))` |
| 卡片圆角 | `var(--radius-card)` |
| 卡片表面 | `var(--color-surface-elevated)` |
| 卡片边框 | `var(--color-border-strong)`，低对比 |
| 卡片阴影 | `var(--shadow-card)`，仅一层 |
| 区域间距 | `var(--learning-section-gap)` |
| 判断按钮间距 | `var(--learning-action-gap)` |
| 答案预留最小高度 | `calc(24px * var(--font-scale))` |

布局要求：

- 卡片占据学习内容区的主要视觉面积，但不填满 viewport。
- 卡片宽度随容器变化，禁止固定像素宽度造成横向溢出。
- 卡片高度以内容自然撑开为主，不使用无条件的大 `min-height` 制造空白。
- 答案显示可以使页面纵向增长，但不应造成横向溢出或按钮被遮挡。
- `box-sizing: border-box`、`min-width: 0` 和自然换行必须覆盖长文本场景。

## 5. 字体与层级

沿用项目现有字体栈和 `--font-scale`，不为 Word Card 引入新字体依赖。

| 层级 | 角色 | 视觉要求 |
|---|---|---|
| Display | 单词 / 当前提示 | 最大字号，清晰、稳定，不使用过度压缩字距 |
| Answer | 答案内容 | 低于当前提示一级，显示后获得明确但克制的强调 |
| Action | 显示答案 / 判断按钮 | 文本清晰，按钮尺寸稳定，语义不只依赖颜色 |
| Meta | 编号 / 模式 / 进度 | 辅助层级，不与单词竞争焦点 |
| Caption | 快捷键 / 保存说明 | 最低强调，但必须可读 |

字号必须兼容 `100% / 125% / 150% / 175%` 缩放。字体放大时，优先增加纵向空间和换行，不得压缩正文、按钮点击区或答案内容。

## 6. 状态规格

### 6.1 Neutral / 答案隐藏

显示：当前提示、编号、可选音标、答案预留区和“显示答案”按钮。

要求：

- 单词正文是唯一主焦点。
- `显示答案` 使用学习页 primary action 语义。
- `认识` 与 `不认识` 不可执行，但位置保持稳定。
- 不显示答案、例句、分数、倒计时或自动揭示提示。

### 6.2 Answer Revealed / 答案已显示

显示答案后，答案内容进入预留区域；卡片整体不应发生明显跳动。

要求：

- 答案区域可以短暂淡入，但不能阻塞按钮或快捷键。
- `显示答案` 进入 disabled 状态，判断按钮启用。
- `认识` 与 `不认识` 保持相近宽度、相同高度和同等权重。
- 答案不等于“答对”，不要在尚未判断时使用完成状态视觉。

### 6.3 Known / Unknown / 判断反馈

反馈只确认本次判断已被接受，并进入现有的下一词流程。

- `认识` 使用现有 success 语义。
- `不认识` 使用现有 danger 语义，但避免高饱和警报式红色。
- 颜色必须同时配合文字、位置、边框或图标表达语义。
- 反馈可以使用短暂的边框、背景或 active 变化，不显示分数、连击、奖励或新弹窗。
- 新词出现时清除旧答案和反馈，不残留上一词的视觉状态。

### 6.4 Focus-visible / Disabled

- 键盘焦点使用 `--color-focus` 与 `--shadow-focus`，必须清晰可见。
- disabled 保留原位置和尺寸，统一使用 `--learning-disabled-opacity`。
- hover 不得改变布局、字号或卡片尺寸。
- active 可以有轻微压缩或颜色变化，但不得触发新的业务动作。

## 7. 颜色与主题

Word Card 只使用现有语义 token：

| 用途 | Token |
|---|---|
| 页面背景 | `--color-bg` |
| 卡片表面 | `--color-surface-elevated` |
| 正文与单词 | `--color-text` |
| 辅助信息 | `--color-text-muted` / `--color-text-subtle` |
| 卡片边界 | `--color-border` / `--color-border-strong` |
| 显示答案主操作 | `--color-brand` / `--color-brand-strong` |
| 认识 / 完成 | `--color-success` / `--color-success-surface` |
| 不认识 / 错误语义 | `--color-danger` / `--color-danger-soft` |
| 键盘焦点 | `--color-focus` / `--shadow-focus` |

深色和浅色主题必须保持相同的信息层级、内容顺序、按钮位置和交互语义。主题差异只体现在 token 映射，不在 Word Card 内创建独立颜色。

## 8. 响应式行为

### `920×620` 紧凑窗口

- 顶部信息允许自然换行，不能压缩单词正文。
- 减少卡片空白和辅助间距，但保留可读的点击区域。
- 页面允许纵向滚动，禁止横向溢出。
- 长释义与答案优先完整显示。

### `1180×760` 标准窗口

- Word Card 保持明确的中心视觉位置。
- 标题、模式、进度和计数可保持紧凑排列。
- 卡片与判断操作之间形成稳定节奏，不使用过大的上下留白。

### 宽屏与全屏

- 通过最大宽度限制防止单词和释义拉得过宽。
- 不因为可用空间增加而无限放大正文。
- 增加外围呼吸空间，而不是增加新的信息模块。

## 9. 动效与可访问性

- 微交互使用 `--duration-fast`，答案和页面状态使用 `--duration-standard`。
- 只优先动画 `opacity` 和 `transform`，避免大范围布局重排。
- 切换单词不得延迟保存、改变索引时机或造成重复提交。
- `prefers-reduced-motion: reduce` 下移除位移、连续动画和非必要过渡。
- 重要语义必须有文本，不能只依赖颜色、图标或动效。
- 所有按钮必须有可见焦点、可读名称和足够点击区域。
- 单词、答案和中文长文本必须支持自然换行与辅助技术读取。

## 10. 人工验收清单

- [ ] 卡片在页面上是唯一主要视觉焦点。
- [ ] 答案隐藏、答案显示和判断反馈的阶段差异一眼可辨。
- [ ] 显示答案后卡片和判断按钮没有明显布局跳动。
- [ ] 长单词、长释义、中文多行文本和字体放大均不裁剪、不溢出。
- [ ] `920×620`、`1180×760`、宽屏和全屏均无横向溢出。
- [ ] 深色与浅色主题共享相同语义层级，文字和焦点状态可读。
- [ ] 鼠标与现有快捷键产生一致的视觉状态。
- [ ] reduced-motion 环境下仍能完成完整学习流程。
- [ ] 未新增业务字段、业务状态、数据流、快捷键或学习功能。

## 11. 实现边界

允许修改学习页的 JSX 展示结构、CSS 布局、token 映射、状态 class 和可访问性属性；不允许借由视觉实现修改学习逻辑、数据结构、保存流程、IPC 或快捷键语义。

如视觉需求与现有业务行为冲突，以保持现有学习流程和数据一致性为先，并在人工审核节点记录取舍。
